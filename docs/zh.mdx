<a id="example-release-work" />

发布 Rudder 0.5.0 需要实现、验证、评审和发布决定。Rudder 正是为这种工作而设计：多位参与者共同提供证据，最后由人判断结果是否可以交付。

## Agent 工作需要共同记录

Rudder 是开源的 Agent 团队协作平台。它把目标、Chat、Issue、Agent、运行记录、产物、评审、预算和可复用指令连在一起，但不替代真正执行工作的运行环境。

Agent 是有固定职责和配置的团队成员。Agent 运行是它的一次有边界的执行。Codex、Claude Code、本地进程或 webhook 才是被 Rudder 调用的运行环境。

![Rudder 工作空间概览](../images/board-overview.png)

## 为什么要保留工作链

一次漂亮的回答很容易淹没在终端或长对话里。Rudder 会把前因后果放在可检查的位置：

- 目标和项目说明为什么要做
- Chat 或 Issue 保存请求与上下文
- Agent 运行和对话记录说明执行过程
- 文件、链接、截图等产物呈现结果
- 评审结论、阻塞、审批和下一位负责人说明接下来怎么办

想通过持续对话澄清、调整并完成任务时，用 Chat。需要指定负责人、跟踪依赖、显示状态或安排评审时，用 Issue。两种入口都能完成真实工作。

## 从一件小事开始

先安装 Rudder，再从自己的工作里选一个边界清楚的部分。第一次只走完一个请求、一次运行、一个可检查的产物和一次评审决定。这正是 0.5.0 发布记录能够发挥作用的同一条工作链。

```bash
npx @rudderhq/cli@latest start
```

打开应用，创建组织，然后在 Chat 中把你的请求交给默认 Agent。如果这件事需要指定评审人或跟踪依赖，就创建 Issue。
