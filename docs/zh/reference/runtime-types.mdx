<a id="definition" />

## 定义

运行环境是执行 Agent 运行的适配器。Agent 是长期存在的团队成员，运行是
一次有边界的尝试，运行环境则为这次尝试提供本地或外部执行能力。

<a id="states" />

## 状态

标准 Agent 配置界面目前可使用以下本地选项：

| 界面选项 | 运行环境值 | 本地命令 |
| --- | --- | --- |
| **Codex (local)** | `codex_local` | `codex` |
| **Claude Code (local)** | `claude_local` | `claude` |
| **Cursor (local)** | `cursor` | `cursor-agent` |
| **Gemini CLI (local)** | `gemini_local` | `gemini` |
| **OpenCode (local)** | `opencode_local` | `opencode` |
| **Pi (local)** | `pi_local` | `pi` |

可用性只是安装提示：

| 就绪分组 | 含义 |
| --- | --- |
| **Ready on this machine** | 服务端能在 PATH 中找到默认本地命令 |
| **Needs setup** | Rudder 没有找到默认命令 |
| **Other runtimes** | Rudder 无法通过本地命令探测判断是否就绪 |

配置后应运行 **Test runtime chain**。探测成功比可用性分组更能说明实际状态。

<a id="constraints" />

## 约束

各运行环境的能力不同。Codex、Claude Code、OpenCode 和 Pi 可以通过受支持
的 MCP 或原生桥接获得 Rudder 托管工具。Cursor 和 Gemini 使用各自的适配器
行为。远程或不支持的适配器不能声称拥有并不存在的托管工具路径。

模型发现、会话复用、技能同步、记录解析、成本元数据和运行中控制都由具体
适配器决定。备用运行环境是另一次明确尝试，不能证明主运行环境具有相同能力。

<a id="boundaries" />

## 边界

通用 `process` 和 `http` 适配器属于内部或高级能力，不会作为普通运行环境
选项出现。界面中显示为不可用或即将提供的注册项，并不表示当前配置可执行。

Rudder 准备托管状态和本次任务选中的上下文，运行环境负责执行。运行环境配置
不会增加 Issue、组织、文件系统、凭据或内置浏览器权限。

<a id="examples" />

## 例子

- 本地 Codex Agent 需要访问代码仓库和 Rudder 工具。选择 `codex_local`，
  配好模型与权限，再通过 **Test runtime chain** 验证后分配工作。
- OpenCode 命令已经安装，但缺少服务商登录。它可能显示为可用，完整测试仍会
  报认证失败。修复服务商配置后重新测试。
- 某个运行环境不支持原生运行中转向。Rudder 应如实说明“中断后继续”的备用
  路径，不能返回原生 **Steer** 已成功的假象。
