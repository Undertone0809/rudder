<a id="definition" />

## 定义

这些记录让 Agent 工作可以被检查。审批约束拟执行的动作，预算限制费用，活动
记录保存重要的产品变更，运行证据解释执行过程。Dashboard、Calendar 和提醒
页面从这些来源生成摘要，不会另外维护一套状态。

<a id="states" />

## 状态与记录

<a id="approvals" />

### 审批

一条审批记录会保存请求动作、目标、申请人、状态、讨论、结论和应用结果。
请求被接受后，由该动作所属的服务执行。应用过程可以安全重试，并始终受组织
范围约束。

| 状态 | 含义和下一步 |
| --- | --- |
| `pending` | 等待结论；可以接受、拒绝或要求修改 |
| `revision_requested` | 需要修改；申请人可以重新提交到 `pending`，期间仍可作出结论 |
| `approved` | 动作已获授权；所属服务以可安全重试的方式应用 |
| `rejected` | 动作被拒绝，不会应用 |
| `cancelled` | 请求在没有结论、也没有应用动作的情况下结束 |

只有 `pending` 可以进入 `revision_requested`。`pending` 和
`revision_requested` 都可以被接受或拒绝；只有 `revision_requested` 可以重新
提交。`approved`、`rejected` 和 `cancelled` 是这条审批记录的终态。

<a id="budgets-and-cost" />

### 预算和成本

运行环境和结果写入会产生带来源身份的成本事件。在支持的地方，Rudder 可以按
组织、Agent、项目、Issue、运行和时间窗口汇总。月度周期使用 UTC。软提醒用于
显示费用压力；达到硬限制后会暂停或阻止新工作，而不是事后才报告。

<a id="activity" />

### 活动记录

活动记录是跨页面的重要变更审计线索。每条记录保存参与者、组织、动作、对象、
引用和摘要，也可以连接相关的 Chat、Issue、运行和审批上下文。

<a id="run-intelligence" />

### 运行信息

组织运行列表默认返回有边界的摘要，包括身份、状态、时间、Agent 与运行环境、
目标、结果或错误、用量与成本、技能证据和日志可用性。需要完整结果、上下文、
记录、事件或日志时，再打开单条运行。原始证据不会被摘要替代，支持的详情读取
会按有边界的页面返回。

<a id="dashboard-calendar-and-inbox" />

### Dashboard、Calendar 和人员提醒

Dashboard 根据实时领域记录汇总组织状态。Calendar 保留日期事件，并链接回
来源自动化、Issue、运行或已配置日历来源。Inbox、侧栏计数和 Messenger 把需要
人处理的事项带回对应来源对象。

<a id="constraints" />

## 约束

- 评审判断产物质量，审批授权受治理动作，两者不能互相替代。
- 达到预算硬限制后，新产生的隐性工作会停止。成本事件保留来源运行或事件身份。
- 活动记录只保存重要变更，不记录每次内部更新。
- 运行摘要不能替代诊断和评审所需的记录、结果、日志、事件或关联产物。

<a id="boundaries" />

## 边界

所有记录都受组织范围约束。人员提醒和未读状态不能跨组织泄漏。Dashboard 和
Calendar 是派生页面，不会重新定义 Issue、运行、审批、成本或自动化状态。

摘要提出疑问时，应打开所属详情页。活动记录说明发生了什么变化；来源 Issue、
运行、审批或自动化保存完整记录和可执行的下一步。

<a id="examples" />

## 例子

- Agent 提议执行敏感变更。审批记录保存动作内容和讨论；接受后，所属服务只
  应用一次，并留下活动证据。
- Agent 的月度预算达到硬限制。新工作暂停或被阻止，成本页面仍保留组成总额的
  事件。
- Dashboard 显示一次失败运行，Inbox 要求人处理。先打开来源运行查看记录和
  日志，再到关联工作对象作出下一步决定。
