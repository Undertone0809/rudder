<a id="definition" />

不确定一项决定或运营问题应该去哪里处理时，查阅本页。

<a id="states" />

## 去哪里看

| 问题 | 打开 |
| --- | --- |
| 这项敏感操作是否允许发生？ | 审批 |
| 一个 Agent 或项目花了多少？ | 费用 |
| 谁修改了这条记录？ | 活动 |
| 某一次尝试发生了什么？ | Agent 运行 |
| 整个组织哪些工作在推进或等待？ | Dashboard |
| 某一天发生或计划了什么？ | Calendar |
| 现在有哪些事情等我回复？ | Messenger |

<a id="approvals" />

## 审批

审批允许或拒绝一项计划中的操作。它不同于评审：评审判断产物是否合格，审批决定
操作是否有权发生。

审批可以是 `pending`、`revision_requested`、`approved`、`rejected` 或
`cancelled`。请求应说明具体操作、风险、申请人和相关上下文。重复处理同一请求，
不能把操作执行两次。

<a id="budgets-and-cost" />

## 预算和费用

预算可以限制组织或 Agent。费用仍可按项目归因和查看，但项目本身不再设置预算
限制。达到硬限制后，Rudder 会暂停受影响的 Agent 或组织，不能继续产生隐藏花费。

失败或取消的运行仍可能有费用。服务商没有提供用量时，会显示为不可用，不会用
错误的零来代替。

<a id="activity" />

## 活动

活动保存重要操作的变更历史，例如状态改变、分配、评论、评审结论、审批结论和
配置修改。记录会说明谁在什么时候修改了什么，以及影响了哪个组织内对象。

“谁改了这项设置？”适合查活动；真实产物和执行过程仍应看原任务或运行。

<a id="run-intelligence" />

## Agent 运行

组织运行列表会显示简短摘要，包括 Agent、任务、状态、结果或错误、可用的用量
与费用、技能使用和日志状态。打开单条运行，可以查看完整结果、对话记录、事件或
原始日志。

摘要方便快速浏览，但不会删除底层细节。

<a id="dashboard-calendar-and-inbox" />

## Dashboard、Calendar 和 Messenger

- **Dashboard** 汇总当前进展、失败、费用和需要注意的事项。
- **Calendar** 把计划和已经完成的工作放到时间线上。
- **Messenger** 汇总需要人回复的提问、失败、阻塞、评审和审批。

三个入口都会带你回到原始 Chat、Issue、运行、自动化或审批。

<a id="constraints" />

## 需要记住的规则

- 评审判断质量，审批授予权限。
- 配置硬预算后，达到限制必须停止或暂停花费。
- 活动说明记录怎样变化，运行详情解释执行过程。
- 汇总页面不会变成第二份任务状态。

<a id="boundaries" />

## 组织范围

审批、预算、活动、运行、Dashboard、Calendar 和 Messenger 都只属于自己的
组织。在一个组织中创建的凭据，不能打开另一个组织的记录。

<a id="examples" />

## 例子

- 发布说明写得很好，但真正发布仍需要单独审批。
- Agent 达到月度硬预算，在下一次运行前暂停。
- 评审人想知道谁重新分配了 Issue，于是检查活动。
- 负责人从 Messenger 看到自动化失败，并打开来源运行。
