<a id="definition" />

不确定文件应该放在哪里，或者 Agent 会收到哪些文件时，查阅本页。

<a id="states" />

## 位置速查

| 位置 | 用途 | 常见内容 |
| --- | --- | --- |
| Library | 人和未来 Agent 还要找到的长期文件 | 简报、笔记、已接受报告 |
| 项目资源 | 项目运行开始时选择性提供的上下文 | 少量相关 Library 文件或链接 |
| 项目工作区 | 进行项目工作的文件夹或仓库 | 源代码、网站、工作文档 |
| 运行工作区 | 一次运行实际使用的文件系统或分支 | 本次运行的改动 |
| Agent 目录 | 某个 Agent 的托管状态 | 指令、记忆、技能 |
| 工作区备份 | 保存下来的组织工作区版本 | 用于检查或恢复的文件 |
| 临时目录 | 短期临时数据 | 下载、缓存、中间文件 |

默认本地 Desktop 会把组织文件映射到 `~/Documents/Rudder` 下。修改组织名称
不会悄悄移动文件夹。

<a id="constraints" />

## 防止意外暴露上下文的规则

- 项目运行只会收到已经选择的项目资源，不是整个 Library。
- Agent 指令、技能、凭据和缓存不是普通 Library 内容。
- 产出的文件应继续连接到它所属的 Chat、Issue、运行或项目。
- 浏览器或服务端部署不能借助 Desktop 打开文件功能，任意访问本地应用。

<a id="boundaries" />

## 安全恢复和归档

- 映射的组织文件夹消失时，应恢复原目录或使用备份，不能用空目录代替。
- 恢复前检查所选备份；Rudder 会先创建安全备份。
- 还有未完成 Issue 依赖某个运行工作区时，不能归档。
- 编辑文件提示版本过期时，先比较两份内容，再决定保留哪一份。

<a id="examples" />

## 例子

- 把确认过的客户资料放进 Library，再只选择当前项目需要的几份。
- 让代码 Agent 修改项目工作区，把分支或隔离目录保留在运行记录上。
- 从评审 Issue 链接最终报告，不要让它只存在于对话记录里。
