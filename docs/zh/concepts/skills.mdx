<a id="definition" />

## 技能是什么

技能是一套可以反复用于某类工作的指令。它可以说明怎样检查发布、排查失败运行、
准备报告，或执行其他稳定流程。

技能适合保存**重复工作应该怎样做**。当前任务的事实留在 Chat、Issue、项目或
Library 中；Agent 的长期职责则写在 Agent 指令里。

<a id="case" />

## 例子：发布检查

经过几次发布后，团队发现每次评审都要重复同一套有效检查：确认软件包版本、
测试安装程序、检查发布说明，并说明回滚位置。团队把这套稳定步骤整理成技能。

下一次发布时，Agent 可以直接复用流程，不必再复制一段长 Prompt。最终结果是否
合格，仍然由评审决定。

<a id="when-useful" />

## 什么时候值得创建

满足以下条件时再创建技能：

- 同一做法已经成功使用过不止一次
- 什么时候使用、应该得到什么结果都很清楚
- 未来多个任务或 Agent 都会受益
- 流程变化后有人会维护它

不要把每次纠正都变成技能。一次性偏好留在当前对话；会影响未来工作的稳定经验，
应先经过评审。

<a id="operating-boundaries" />

## 可以使用，不代表真的使用过

Rudder 可以发现并为 Agent 启用一项技能，但运行工具仍然需要加载并实际应用。
运行详情会尽可能显示它是否真正使用了这项技能。

反馈不会自动改写技能。只有当经验、适用范围、验证方式和撤销方法都清楚后，才
更新长期指令。

参见[评审、反馈和改进](/zh/concepts/reviews-feedback-learning)。
