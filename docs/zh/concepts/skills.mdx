<a id="definition" />

## 定义

技能是一套可复用的操作步骤，Agent 可以在处理某类工作时查阅。技能来源可以是 Rudder 内置集合、组织技能库、Agent 文件夹、用户级来源或运行环境自己的目录。

四种状态需要分开理解：

| 状态 | 含义 |
| --- | --- |
| 已发现 | Rudder 可以把技能显示为候选项 |
| 已启用 | Rudder 为某个 Agent 或某次运行选中了它 |
| 已加载 | 运行环境已经收到或挂载了它 |
| 已使用 | 运行证据表明运行环境确实应用了它 |

这些状态不能互相替代。技能已加载，不等于已经使用。

<a id="case" />

## 一个示意案例

某个发布团队每次都要检查发布说明、软件包和回滚信息。经过几次评审后，团队把稳定步骤整理成发布检查技能。发布 Agent 在下次任务中可以沿用同一套说明，但每次运行仍要分别记录是否有证据表明它真正使用了该技能。

<a id="when-useful" />

## 什么时候有用

一套步骤已经重复出现，触发条件清楚，而且以后还要复用时，可以整理成技能。只属于当前任务的事实应留在 Chat、Issue、项目资料或 Library 中；长期职责要求应留在 Agent 操作说明中。

Rudder 提供一组数量有限、始终可发现的内置技能，用于产品说明、记忆文件、技能创建和可视化。可发现只是为了让运行环境在相关任务中找到它，并不要求模型每轮都使用全部技能。

<a id="operating-boundaries" />

## 操作边界

Rudder 会为每次运行解析技能集合。运行环境能够看到某个目录，并不代表其中的平台内置技能、旧技能、项目技能或用户目录技能自动成为这个 Agent 已加载的 Rudder 技能。适配器必须移除、隔离或忽略不在选中集合中的条目。

风险最高的是行为被悄悄改写。反馈不会自动修改技能。只有证据、适用范围、评审以及回滚或评估方式都清楚后，才应把经验写入技能。相关区别见[评审、反馈和学习](/zh/concepts/reviews-feedback-learning)。
