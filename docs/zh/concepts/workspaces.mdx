Rudder 使用几个不同的文件位置，因为参考资料、工作文件和最终产物需要不同的
处理方式。

<a id="definition" />

## 文件应该放在哪里

| 位置 | 适合放什么 |
| --- | --- |
| Library | 团队或未来 Agent 还需要找到的文件 |
| 项目资源 | 每次项目运行开始时真正需要的少量 Library 或外部资料 |
| 项目工作区 | 进行项目工作的代码仓库或文件夹 |
| 运行工作区 | 一次 Agent 运行实际使用的文件夹或分支 |
| Agent 目录 | 某个 Agent 的托管指令、记忆和技能状态 |
| 工作区备份 | 可以检查或恢复的组织工作区版本 |

项目资源是一份经过挑选的起始资料，不代表运行可以读取组织里的所有文件。

<a id="case" />

## 例子：准备一份客户简报

把客户确认过的来源资料放进 Library，只把这次项目真正需要的几份资料加到项目。
让 Agent 在项目仓库中工作，再把通过确认的简报保存回 Library，并从 Chat 或
评审 Issue 链接过去。

下一个 Agent 因此可以找到正式结果，而不会继承第一次尝试留下的所有临时文件。

![工作区与资源](../../images/workspaces-resources.png)

<a id="when-useful" />

## 一条简单规则

- **以后还要复用的输入：**放进 Library 或项目资源
- **允许 Agent 修改的文件：**放在项目或运行工作区
- **最终结果：**继续连接到产生它的 Chat、Issue、运行或项目
- **临时文件：**默认不要放进 Library

标准本地 Desktop 安装会把组织文件映射到 `~/Documents/Rudder` 下的目录。

<a id="operating-boundaries" />

## 安全恢复

Agent 指令、托管技能、凭据和缓存目录不是普通 Library 文件。如果映射的组织
文件夹消失，应恢复原目录或使用备份，不能新建一个空目录后假设数据没有问题。

恢复前先检查备份内容。Rudder 会先创建安全备份。还有未完成 Issue 依赖某个
运行工作区时，需要先关闭或移动这些任务，才能归档工作区。

准确位置和平台差异见[工作区位置参考](/zh/reference/workspace-boundaries)。
