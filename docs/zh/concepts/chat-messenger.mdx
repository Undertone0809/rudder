Chat 和 Issue 是两种完成任务的方式。Messenger 用来找到 Agent 提问、运行失败、
待评审等需要你处理的事情。

<a id="chat-or-issue" />

## 默认从 Chat 开始，需要时再增加结构

| 情况 | 使用 |
| --- | --- |
| 想在一段对话里提出要求、澄清、执行和修改 | Chat |
| 一个人可以在对话中判断结果 | Chat |
| 任务需要负责人、状态、依赖或评审人 | Issue |
| 团队流程要求共享队列或特定字段 | Issue |

Chat 不是“正式工作”开始前的临时收件箱。任务可以从第一条请求一直在 Chat 中
完成并被接受。只有额外协调确实有用时，才创建或关联 Issue。

![需要时从 Chat 创建 Issue](../../images/chat-create-issue-proposal.png)

## 让结果留在发生工作的地方

在 Chat 中，请求、Agent 运行、后续修改和最终回答会留在同一段对话里。文件与
链接区域会分开显示：

- **产物：**Agent 真正创建的文件或链接
- **来源：**你或项目提供的材料
- **参考：**Agent 引用或推荐的材料

回复里提到一个链接，不代表它是 Agent 的产物。如果工作属于 Issue，就把结果
和评审结论留在那条 Issue 上。

## 用 Messenger 找到正在等你的事情

Messenger 会汇总 Rudder 各处需要注意的内容：

| 看到的内容 | 去哪里处理 |
| --- | --- |
| Agent 提问 | 原始 Chat 或 Issue |
| 一次运行失败 | 运行记录和它所属的任务 |
| 工作被阻塞 | 正在等待回答或负责人的记录 |
| 结果等待评审 | 对应 Issue 和产物 |
| 操作等待审批 | 对应的审批 |

Messenger 负责把你带回来源，不是第二套任务看板。把对话放进自定义分组，也不会
改变它的负责人、状态或评审人。

![Messenger 待处理事项](../../images/messenger-approvals.png)

## 只调整当前对话

每段 Chat 都可以选择 Agent；运行工具支持时，还可以选择模型和思考强度。这些
选择只用于当前对话，不会改写 Agent 在其他地方的默认配置。

想探索另一条路线，又不想改变原对话时，使用**分支**。只想在主任务旁边追问一个
局部问题时，使用**侧边对话**。

## 对回复中的一小段继续提问

选中 Agent 回复中的文字，然后选择**添加到对话**，就能把准确段落附在下一条
消息中。这样可以直接指出要改哪里，不必复制整段回复。消息发出后，这段引用会
继续作为上下文保留。

## Agent 工作时又发了一条消息

Rudder 会把消息排成后续请求；运行工具支持时，也可以用它调整当前运行方向。
输入框会说明接下来采取哪种方式。当前方向已经没有价值时，选择**停止**。
