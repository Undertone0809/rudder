<a id="definition" />

## 定义

插件是由 Rudder 宿主安装和管理的可选软件包。它可以声明工具、状态、HTTP 访问、界面插槽、事件订阅、webhook、后台任务和宿主服务访问。

宿主会校验清单，启动或停止工作进程，为每次桥接操作检查已声明能力，并保存状态、配置、日志、任务、webhook 和插件数据供负责人检查。插件工具使用带命名空间的名称，不能覆盖核心工具或其他插件工具。

<a id="case" />

## 一个示意案例

一个团队安装了 CRM 插件，为项目增加客户面板和定时账户同步。插件配置写明外部服务，后台任务明确归属于该插件，同步失败时可以在插件日志中查到。CRM 面板可以链接到 Rudder 工作，但不能建立新的 Issue 状态，也不能绕过原有审批流程。

<a id="when-useful" />

## 什么时候有用

可选集成或专门界面不适合进入 Rudder 核心工作循环时，用插件。常见用途包括服务连接器、自定义工具、后台任务、webhook、界面组件和运维视图。

目标、Chat、Issue、Agent 运行、评审、审批、预算和工作区仍由内置产品对象负责。插件可以通过宿主 API 连接这些对象，但不拥有它们的规则。

<a id="operating-boundaries" />

## 操作边界

插件只能做增量扩展。它不能覆盖核心路由或名称，不能通过未声明状态跨越组织范围，也不能绕开公共宿主 API 去修改审批、身份验证、Issue 签出或预算执行规则。

风险最高的是信任边界。插件工作进程和前端软件包都是安装到本机的代码，不是用来运行不可信软件包的安全沙箱。启用前应检查来源、声明的能力、配置、外部服务和版本变更。卸载必须通过宿主生命周期完成，不能删除核心 Issue、审批、预算或运行历史。

按照[管理插件](/zh/how-to/manage-plugins)完成安装和检查。
