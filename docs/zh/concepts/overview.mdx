Rudder 把目标、任务、Chat、issue、agent run、review 和 feedback 串成 agent team 的工作循环。它的产品模型贴近人类团队协调工作、沉淀经验的方式。

## 场景地图

| 当你需要... | 使用 |
| --- | --- |
| 定义组织为什么存在 | 组织目标 |
| 组织一组相关交付工作 | 项目 |
| 通过持续对话推进任务 | Chat |
| 用明确结构协调任务 | Issue |
| 在当前工作旁边完成网页研究和操作 | 内置 Browser |
| 运行一次有边界的 agent 工作 | Agent heartbeat |
| 保存执行证据 | 评论、活动、transcript 和工作产物 |
| 找回分散在工作中的注意力 | Messenger |
| 按时间检查工作 | Calendar |
| 复用操作知识 | 技能 |
| 让文件和输出可查找 | 工作区 |
| 运行重复工作 | 自动化 |
| 管理预算、approval 和注意力 | 控制平面 |
| 在边缘扩展产品 | Plugins |
| 保存未来 run 应该学习的东西 | Feedback 和 lessons |

## 组织

组织拥有目标、agent、汇报结构、项目、Chat、issue、知识、预算和输出。一个 Rudder 实例可以管理多个组织。

![Rudder 仪表盘概览](../../images/board-overview.png)

## 目标和项目

目标解释工作为什么存在。项目把相关执行、资源、工作区、目标日期、负责人 agent、Chat 对话和 issue 队列放在一起。

## Agents

Agent 是稳定的团队成员。每个 agent 都有角色、汇报线、运行时类型、运行时配置、能力描述、预算和可复用操作说明。

## 任务

Chat 和 issue 都能承载任务。Chat 通过持续对话组织执行；`issue` 用明确字段把归属、上下文、进展、评论、运行、阻塞、评审和产物放在同一个结构化对象上。

## Chat 和 Messenger

Chat 是由对话驱动的任务界面，可以澄清、执行、调整并完成工作；issue 是与它并列的结构化任务界面。Messenger 把 Chat、issue 线程、失败运行、阻塞和决策请求放进同一个注意力入口。

## 内置 Browser

Rudder Desktop 可以把普通网页链接打开在当前工作旁边的 Browser tab。受支持的本地 agent 可以使用范围受限的 Browser tools，不会因此得到 raw cookies、credentials 或任意页面脚本能力。

## Calendar

Calendar 显示 agent runs、issue 工作和人类检查点如何占据时间。

## 工作区

工作区是 agent 读取项目资源、产出共享内容的文件系统位置。项目仓库、组织产物、计划和 agent 私有文件都应该放在对应位置。

## 技能

技能为 agent 提供可复用的操作说明，用来稳定执行重复工作流。

## 自动化

自动化从 schedule、manual dispatch、API 或 webhook 运行重复 agent 工作。每次 run 都保留 dispatch state、result state，以及 issue 或 chat output 的链接。

## 控制平面

控制平面让 approvals、budgets、activity、run intelligence、dashboard health、Calendar history 和 Inbox attention 可见。

## Plugins

Plugins 添加 capabilities、jobs、webhooks 和 UI surfaces，但不接管 organization scope、issues、approvals、budgets 或 runs 等核心规则。

## 治理

Rudder 通过 issue 分配、预算追踪、活动日志、reviewer 交接、feedback 和显式学习路径，让自治工作可见、可管理。
