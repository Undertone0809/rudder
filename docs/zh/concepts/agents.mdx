Rudder 会分开表示长期合作的角色、真正执行工作的程序，以及它的每一次尝试。

<a id="definition" />

## 三个部分

| 部分 | 可以理解成 | 例子 |
| --- | --- | --- |
| Agent | 有职责、指令、技能、权限和预算的长期队友 | 发布文案 Agent |
| 运行工具 | 真正执行任务的程序或服务 | Codex CLI 或 Claude Code |
| Agent 运行 | 一次独立尝试，包含进度、结果、用量和错误 | 发布文案第二稿 |

Rudder 负责协调任务并保存记录，运行工具负责真正执行。

<a id="case" />

## 例子：负责每次发布的文案 Agent

如果每次发布都需要写文案，可以创建一个“发布文案” Agent，为它选择合适的运行
工具和指令。每份公告都会产生一条新的运行记录，但 Agent 会保留同一职责，并且
可以复用经过确认的技能。

第一稿不合适时可以再试一次。此时仍然只有一个 Agent，但有两条独立运行记录，
所以每次尝试的结果和费用都很清楚。

<a id="when-useful" />

## 什么时候需要新建 Agent

一类重复工作需要不同职责、运行工具、指令、预算或权限时，再创建新 Agent。
只是偶尔出现、而且符合现有职责的请求，直接交给已有 Agent。

运行可以从 Chat、已分配的 Issue、评审请求、自动化或手动操作开始。入口会变，
但 Agent 与单次运行的区别不会变。

<a id="operating-boundaries" />

## 运行记录里能看到什么

- 回答或完成摘要
- 产生的文件、报告、截图或链接
- 运行工具提供的用量和费用
- 可用的对话记录、工具操作、日志和最终错误

不同运行工具支持的能力不同，Rudder 会如实显示这些差异。停止或失败的运行即使
已经输出一部分文字，也不能自动算作完成。

支持的选项见[运行工具类型](/zh/reference/runtime-types)，设置步骤见
[配置 Agent 运行工具](/zh/how-to/configure-agent-runtime)。
