<a id="definition" />

## 自动化会保存什么

自动化把一条会重复使用的请求与下面这些设置放在一起：

- 负责执行的 Agent
- 可选的目标或项目
- 什么情况会启动
- 结果应该发到哪里
- 上一次仍在运行时怎样处理

它可以手动开始，也可以由日程、API 调用或 Webhook 触发。

<a id="case" />

## 例子：每周运营简报

每周一上午，报告 Agent 汇总已经完成的工作、阻塞和本周需要的决定。每次结果会
进入一段新的 Chat，因此不会和上周的简报混在同一段对话里。

如果简报需要负责人、状态、依赖或正式评审，就让每次运行创建一条 Issue。

<a id="when-useful" />

## 任务稳定后再自动化

先在 Chat 或 Issue 中手动跑通请求。确认下面这些问题后，再创建自动化：

- 什么时候应该运行
- 哪个 Agent 能完成
- 需要哪些上下文
- 有用的结果长什么样
- 谁会发现并修复失败

模板只会预填创建表单，你仍然可以修改。提交表单前不会真正创建自动化。

<a id="operating-boundaries" />

## 避免重复工作

上一次仍在运行时又收到新触发，并发设置可以选择排队、跳过或合并。即使没有创建
新的 Chat 或 Issue，运行历史也会说明发生了什么。

修复 Agent、指令、日程、上下文或结果去向时，可以先暂停自动化。当前界面会使用
浏览器的本地时区创建和编辑日程。

完整步骤见[创建自动化](/zh/how-to/create-automation)。
