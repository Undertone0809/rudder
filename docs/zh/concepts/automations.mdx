<a id="definition" />

## 定义

自动化是一份可以重复执行的 Agent 工作定义。它把操作说明、负责 Agent、可选的目标或项目上下文、触发方式、结果去向、优先级和并发策略放在一起。

触发方式可以是定时、手动或 API，也可以是 webhook。每次分派都会创建自动化运行记录。即使并发或准入规则让这次分派跳过或合并，记录也会保留。它把触发源与后续的 Issue、Chat 和 Agent 运行连接起来。

结果有两种去向。跟踪为 Issue 时，任务进入正常的 Issue 生命周期；发送到 Chat 时，每次真正执行都会新建一段 Messenger 对话。精确差异见[自动化结果去向参考](/zh/reference/automation-output-routing)。

<a id="case" />

## 一个示意案例

运营负责人希望每个工作日傍晚收到简报。自动化指定一名报告 Agent，连接运营项目，并要求汇总已完成工作、阻塞和下一项待决事项。每次执行都会把结果发到新的 Chat，负责人检查当天运行时，不会和前一天的简报混在一起。

<a id="when-useful" />

## 什么时候有用

触发条件、负责人、说明和结果去向已经稳定时，再使用自动化。请求仍在频繁变化时，先留在 Chat 或 Issue 中探索。内置模板只是创建表单中的可编辑起点；负责人提交之前，选择模板不会创建自动化。

当前生命周期只有启用和暂停两种状态。需要保留定义和历史，但暂时停止新分派时，可以暂停；定义准备好再次运行时，再恢复启用。

<a id="operating-boundaries" />

## 操作边界

自动化属于单一组织。关联的目标、项目、父 Issue 和负责 Agent 都必须在同一组织中。定时规则按记录中保存的时区计算；当前界面创建或编辑日程时使用浏览器本地时区。外部触发还必须防止重放和重复处理。

风险最高的是重复工作。并发策略决定已有工作运行时，新分派应该排队、跳过还是合并。即使跳过或合并，运行记录也要说明为什么没有出现新的 Chat 或 Issue；系统不能为此制造空对话。

按照[创建自动化](/zh/how-to/create-automation)完成创建和验证。
