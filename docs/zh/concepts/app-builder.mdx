## 描述业务不用选择技术栈

App Builder 可以把“做一个 cold email 管理系统”或“完善我已有的 CRM”变成本地
Web 产品。在 Rudder 中，用户把它当作 App 使用；底层仍然是运行在当前电脑上的
普通网站。源码保持常规结构，也可以继续用 IDE、终端或普通浏览器打开。

创建新 App 时，App Builder 默认使用 Rudder 维护的 Next.js 全栈脚手架，因此非技术
用户不需要选择基础设施。对于已有的 Next.js、React、Vue、Astro、SvelteKit、Nuxt
或其他 Web 项目，App Builder 会保留原来的框架，并帮助完善产品或准备 Rudder 可
发现的开发脚本。

## 打开 Apps，然后从 Apps 开始

App Builder 默认可用。在 Primary Rail 中选择 **Hub**，然后从 Plugins 空状态或
Showcase 中选择 **Build App**，Rudder 会打开 Apps 工作区。App 准备好后，也可以
从 **Hub > Plugins** 中的 App 卡片直接返回该 App。

点击 Apps 侧栏中的 **+**：

- **Build with Agent** 会打开普通 Chat，并放入一段可编辑的 App Builder 草稿。
  用户可以先和 Agent 澄清需求，再创建或完善产品。
- **Add local web project** 会打开文件夹选择器。用户可以把这台电脑上常用的 Web
  项目装载到 Rudder，并直接在 Rudder 中打开使用。

Rudder 会识别项目的包管理器和受支持的开发脚本，在运行任何代码前展示完整启动
定义供用户审查。注册后的 App 会出现在侧栏，并在 Apps 主工作区以可关闭 Tab 打开。
适用的设置、源码、当前链接、外部浏览器、数据和停止操作收纳在 App 行的 More
菜单中。

Apps Home 仍提供 **Turn ideas into applications**。发送需求后，Rudder 会创建
受管理的 App 记录，并打开普通 `$app-builder` Chat。开发、调试、审查和验证完成后，
Desktop 会再次执行维护好的检查流程，启动仅限本机回环访问的网站，并自动打开成品
App。需要继续优化时，用户可以回到原 Chat。如果验证或启动失败，Rudder 会保留
源码，并提供明确的重试或 Chat 恢复入口。

App 运行时，点击 **Copy App link** 可以复制当前回环地址，在同一台电脑的其他
浏览器中打开。

## App 自己管理数据

生成的 App 可以使用 SQLite、迁移、导入、后台任务和外部集成。CRM 联系人、邮件
正文或营销数据不会被复制进 Rudder 自己的数据库。

新 App 默认使用合成开发数据。用户已有真实数据时，可以在 Chat 中选择副本、
脱敏数据或直接访问。保存业务记录的 App 提供 JSON 导入导出约定。

## 开发数据恢复

官方脚手架把开发数据放在 `data/development/`，并预留
`data/production/` 给正式数据。Apps 右侧信息区可以在 App 停止后备份、导出、导入
和恢复开发数据，不会替换预留的正式数据目录。

集成、业务副作用和后台行为由生成的 App 自己管理。当前版本不提供不可变版本升级、
正式数据迁移/回滚、Rudder 任务调度器或 Secret 绑定 UI。真实数据与外部副作用
决策由 Chat 和 App 自己的控制界面处理。

## 在用户设备运行不提供云端版本

App Builder 不包含云构建、托管、公共 URL、隧道、自定义域名、托管远程数据库或
跨设备同步。模型提供商、依赖下载和外部集成仍可能访问网络。

复制出的 App 链接不是公网分享链接，只能在当前 App 进程运行期间由同一台电脑
访问；停止或重启 App 后，地址可能失效或变化。

用户需要不同技术栈或已经有值得长期使用的产品时，仍可保留现有 Web 项目和普通
编码流程。
