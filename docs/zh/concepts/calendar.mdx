<a id="definition" />

## Calendar 用来做什么

Calendar 按时间显示本来就有日期的工作，包括 Agent 运行、自动化日程与运行，
以及重要的人工检查。

你可以用它回答：

- 昨天有哪些 Agent 工作过？
- 本周有哪些重复任务即将开始？
- 几次高费用运行是否发生了重叠？
- 某次评审或审批是什么时候完成的？

![Calendar 工作历史](../../images/calendar-work-history.png)

<a id="case" />

## 例子：检查每周报告

一份运营简报安排在周一上午。Calendar 会先显示下次计划时间，真正执行后再显示
运行记录。如果报告失败，打开来源自动化或 Agent 运行，查看原因并修复。

<a id="when-useful" />

## Calendar 不会代替任务本身

日、周、月视图只是用不同方式排列同一批来源记录。想修改负责人、回答问题、
评审产物或调整日程时，应回到原始 Issue、Chat、运行记录或自动化。

<a id="operating-boundaries" />

## 需要记住

- Calendar 里出现一条记录，不代表任务已经成功。
- Calendar 不会为 Issue 或自动化再建立一套状态。
- 日程记录只属于自己的组织，并且会链接回来源。
- 来源发生变化时，Calendar 会跟着更新，不需要维护另一份副本。

重复工作见[自动化](/zh/concepts/automations)，等待你处理的问题与失败见
[Messenger](/zh/concepts/chat-messenger)。
