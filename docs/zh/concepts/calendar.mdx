<a id="definition" />

## 定义

`Calendar` 是组织范围内的时间视图，用来展示已经带有日期或时间窗口的工作。事件可以来自自动化日程、Issue 日期、Agent 运行时间段或已配置的日历来源。可以打开的事件会保留指向来源对象的链接。

Calendar 回答某件事何时计划、何时发生。状态、结果和下一步仍由原始 Issue、自动化或运行记录负责。

<a id="case" />

## 一个示意案例

运营简报安排在 18:00。Calendar 先显示定时事件，执行后再显示运行时间段。负责人打开事件，进入自动化，再检查关联的 Chat 结果。如果运行失败，失败应在原始运行和自动化记录中处理，不是在 Calendar 里另改一套状态。

<a id="when-useful" />

## 什么时候有用

需要查看一段时间内的安排、重叠、错过的时间窗口和人工检查点时，用 Calendar。日、周、月视图只改变同一批来源事件的排列方式，不会改变底层记录。

要确认当前负责人或处理待决事项，应回到原始 Issue、Messenger 对话、自动化或 Agent 运行。

<a id="operating-boundaries" />

## 操作边界

Calendar 不是任务分配队列，也不能因为出现了一段运行时间就推断工作成功。所有事件必须保持组织范围和来源身份。

风险最高的是重复状态。Calendar 事件不能变成 Issue 或自动化的第二份状态记录。来源发生变化时，Calendar 应反映来源，而不是维护一份独立事实。

重复日程见[自动化](/zh/concepts/automations)，需要找回人的注意力时见 [Chat 和 Messenger](/zh/concepts/chat-messenger)。
