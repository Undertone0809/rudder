这篇指南会带你从刚安装完成，走到 Agent 完成第一件任务。你会创建组织，
连接平时使用的 Agent 运行工具，然后在 Chat 中拿到一个小而真实的结果。

开始前，请先[安装并打开 Rudder](/zh/get-started/installation)。如果准备使用
Codex 或 Claude Code 等本地工具，请先安装并登录对应的命令行程序。

<a id="first-loop" />

## 1. 创建组织

Rudder 把团队工作空间称为**组织**。输入一个你能认出来的名字，例如项目名、
公司名或个人工作空间名。

先做到这里就够了。目标、项目和更多 Agent 都可以以后再加。

## 2. 连接第一个 Agent

选择电脑上已经能用的运行工具，然后按表单完成设置：

- 平时使用 Codex 或 Claude Code 命令行工具，就选择对应选项。
- 有自己的脚本或 Agent 进程，就选择本地命令。
- 只有在已经准备好远程服务时，才选择 Webhook 或远程方式。

运行环境检查。检查通过表示 Rudder 可以启动这个工具，还不会开始正式任务。
如果失败，根据表单中的提示完成安装、登录或修正命令。

## 3. 交给 Agent 一件有用的小事

打开 Chat，发送一条几分钟内就能判断好坏的请求。例如：

```text
为我的产品写一段简短的发布介绍。

读者：第一次尝试产品的开发者。
需要包括：
- 一句话标题
- 它解决什么问题
- 一个具体例子
- 发布前我还需要回答的三个问题
```

好的第一次请求会说明给谁看、要返回什么，以及有哪些重要限制。不要只写
“测试 Rudder”，因为这样的结果对你没有实际价值。

## 4. 查看执行过程

Rudder 会启动刚才选择的 Agent，并在 Chat 中显示回复。你可以在同一段对话中
补充要求、停止无效运行，也可以在 Agent 工作时继续发送信息。

想看更多细节时，打开这次 Agent 运行。这里会显示使用了哪个运行工具、任务是否
完成，以及可用的对话记录、用量、错误或产物。

## 5. 判断结果

阅读 Agent 的回答，或打开它产出的文件，然后选择最轻量的下一步：

- 在同一个 Chat 中要求修改。
- 结果已经可用，就保存或分享。
- 任务开始需要负责人、依赖、明确状态或独立评审时，再创建 Issue。

当你能从同一段对话中找到原始请求、Agent 的结果以及产生结果的运行记录时，
第一次任务就完成了。

## Agent 无法完成怎么办

打开失败的 Agent 运行，先阅读容易理解的错误说明。常见原因包括运行工具没有
登录、模型或命令不存在、运行工具不能访问目标文件夹，或任务需要额外权限。

修好提示中的问题，再重试这条小请求。在一件简单的 Chat 任务成功前，不必急着
添加更多 Agent、项目或自动化。
