完成本页后，Rudder Desktop 会在你的电脑上打开，之后也可以直接用 `rudder` 命令启动。

首次安装前，请准备好受支持的桌面系统、终端、下载所需的网络，以及为当前用户安装应用的权限。

## 安装并打开 Rudder

运行公开安装命令：

```bash
npx @rudderhq/cli@latest start
```

这条命令会准备可持续使用的 Rudder CLI，按所选发布通道下载便携版 Desktop，并打开应用。CLI 和 Desktop 会保持在同一个版本。

![Rudder CLI 终端流程](../../images/installation-cli.png)

安装完成后，可以直接运行：

```bash
rudder start
```

Desktop 窗口进入组织界面，就说明启动成功。接下来可以创建第一个组织。

## Desktop 无法启动时

正常启动时，窗口只显示 Rudder 标识和动态效果，不会展示技术阶段名称或百分比。短暂停留在这个等待画面并不代表失败。

只有本地托管服务明确报告启动失败后，同一个窗口才会显示可读错误和恢复入口：

- **Try again**：在当前窗口发起一次全新的启动尝试。连续点击不会并行启动多个运行环境，也不会打开多个窗口。
- **Email support**：打开一封收件人为 `zeeland4work@gmail.com`、可以编辑的邮件草稿。Rudder 不会自动发送邮件、上传本地数据或附加工作区文件。如果邮件应用无法打开，请使用 **Copy support email** 和 **Copy diagnostic**。
- **Report on GitHub**：只会打开 Rudder 固定的[公开 GitHub Issues 缺陷报告表单](https://github.com/Undertone0809/rudder/issues/new?template=bug_report.yml)。Rudder 不会替你提交 Issue。如果浏览器无法打开，请使用 **Copy issue link**，自行打开这个固定地址，再用 **Copy diagnostic** 复制诊断信息；粘贴前先检查内容。
- **Technical details**：只展开经过允许、范围受限的字段和路径。**Copy diagnostic** 会复制与支持入口相同的安全诊断信息。路径可用时，**Open data folder** 会打开发生失败的实例文件夹；如果无法自动打开，请复制其中显示的 **Instance folder** 路径，再通过文件管理器打开。

分享前先阅读诊断信息。不要在支持请求中加入凭据、数据库、`.env` 文件或私有工作区内容。

## 更新时还有任务正在运行

打包版 Rudder Desktop 可以在 Agent 运行期间下载并校验更新。是否中断当前工作，由你决定：

- **Update when idle**：保留现有运行，等它们结束后再更新。
- **Stop runs and update now**：取消正在运行的任务，退出 Rudder 并立即更新。
- **Cancel**：继续使用当前版本。

如果更新失败或下载过期，失败状态会留在界面上，并提供重试和版本页面入口。
