运行工具是 Agent 工作时由 Rudder 启动的程序或服务。最快的设置方式，是使用
电脑上已经安装并登录的本地命令行工具。

<a id="completed-state" />

## 这篇指南会验证什么

你会为一个 Agent 设置运行工具，通过环境检查，然后完成一项小型 Chat 任务。
真实任务很重要：测试通过只能证明 Rudder 找到了工具，不能证明它能完成工作。

<a id="prerequisites" />

## 开始前

在 Rudder 所在电脑上安装并登录一个受支持的工具：

| 运行工具 | Rudder 查找的命令 |
| --- | --- |
| Codex | `codex` |
| Claude Code | `claude` |
| Cursor | `cursor-agent` |
| Gemini CLI | `gemini` |
| OpenCode | `opencode` |
| Pi | `pi` |

先在终端里运行一次，确认没有“找不到命令”或登录错误。

<a id="case-backed-steps" />

## 连接到 Agent

1. 打开 Agent，然后编辑**运行工具**设置。
2. 选择已经安装的本地工具。
3. 如果这个工具支持，再选择模型和思考强度。
4. 除非任务确实需要，否则保留高级权限、绕过沙箱、自定义命令和指令文件路径的
   默认值。
5. 选择**测试运行时链路**。
6. 阅读结果：
   - `pass`：Rudder 可以启动运行工具。
   - `warn`：可能可以使用，但需要先理解提示中的限制。
   - `fail`：修复提示中的命令、登录、模型、路径或网络问题。
7. 保存 Agent。
8. 在 Chat 中请求一个安全、明确的小结果，例如两行摘要。
9. 打开 Agent 运行，确认所选工具确实产生了回复。

<a id="success-signal" />

## 检查结果

环境测试通过——或警告内容已经理解——并且真实 Chat 任务完成后，设置才算可用。
运行记录应该显示预期工具，以及正常结果或清楚的阻塞原因。

<a id="recovery" />

## 常见问题

- **找不到命令：**安装命令行工具，或填写正确的受支持命令。
- **登录失败：**先在 Rudder 外登录对应工具，再回来测试。
- **模型不可用：**选择服务商账号可以使用的模型。
- **无法读取指令或工作区：**使用绝对路径，并修复电脑上的文件权限。
- **测试通过但任务失败：**打开运行记录，根据具体服务商、模型、权限或项目访问
  错误修复。

Rudder 会自动给受支持的本地工具提供自己的控制能力，不要重复添加 Rudder MCP
服务。外部 MCP 连接与访问级别属于高级设置，需要时查看
[权限与平台](/zh/reference/permissions-and-platforms)。
