<a id="completed-state" />

## 完成后的状态

完成本页后，一项处于启用状态的每周运营简报已经保存负责 Agent、项目上下文、日程、并发策略和 Chat 结果去向。一次手动测试会生成一段关联对话，并留下可检查的运行证据。

<a id="prerequisites" />

## 开始前

准备一个可以工作的 Agent，以及输入和结果形态已经稳定的重复请求。先决定由谁处理失败、什么条件触发工作，以及每次结果应进入新 Chat 还是跟踪为 Issue。精确差异见[自动化结果去向参考](/zh/reference/automation-output-routing)。

<a id="case-backed-steps" />

## 创建运营简报

1. 打开 **Automations**，新建自定义定义。
2. 命名为“每周运营简报”，选择报告 Agent 和运营项目。
3. 写清报告周期、来源记录、期望章节，以及数据缺失时应该如何说明。
4. 把日程设置为每周一 09:00。当前界面没有时区选择器；日程会按浏览器本地时区保存和显示。
5. 保留 **Send to chat**，让每次真正执行都创建一段独立 Messenger 对话。结果需要明确负责人、状态、依赖或评审时，改为跟踪 Issue。
6. 选择运行重叠时的并发方式。重复报告会造成问题时，选择跳过或合并。
7. 保存自动化，然后手动分派一次。
8. 打开运行历史并进入关联 Chat，检查输入消息、Agent 回复、来源 Agent 运行和终止状态。

选择内置模板只会填充一份可编辑草稿。提交定义之前，Rudder 不会创建自动化。

<a id="success-signal" />

## 成功信号

自动化详情显示已经保存的定义、下次计划时间、结果模式和测试运行。测试运行创建一段新的关联 Chat，其中有可用结果，或清楚可见的失败证据。

<a id="recovery" />

## 恢复

没有出现工作时，先检查自动化运行。跳过或合并的记录应写明并发原因，而且不能创建空 Chat。如果 Chat 结果已经开始后执行失败，应进入关联对话和 Agent 运行查看部分结果或后备证据。

修正负责人、上下文、日程、运行环境或结果去向，再手动测试一次。修复期间先暂停自动化，避免定时触发继续制造新尝试。
