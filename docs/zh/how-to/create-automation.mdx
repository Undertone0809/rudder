只有同一条请求已经能稳定手动完成时，才适合自动化。这个例子会创建一份每周运营
简报，并把每次结果发到新的 Chat。

<a id="completed-state" />

## 这篇指南会创建什么

一项启用中的自动化，包含一个 Agent、周一日程、项目上下文、重复运行处理方式，
以及一次成功的手动测试。

<a id="prerequisites" />

## 开始前

你需要一个已经能工作的 Agent 和一条可重复请求。先决定：

- 什么情况应该启动
- Agent 需要哪些信息
- 结果应该包含什么
- 谁负责处理失败
- 结果应该进入 Chat 还是 Issue

一个人读完后可以继续对话的报告适合 Chat；每次结果都需要负责人、状态、依赖或
评审时，使用 Issue。

<a id="case-backed-steps" />

## 创建每周简报

1. 打开**自动化**，创建自定义自动化。
2. 名称填写“每周运营简报”。
3. 选择报告 Agent 和相关项目。
4. 写明报告时间范围、来源、必须包含的部分，以及数据缺失时怎样说明。
5. 把日程设为周一 09:00。当前表单使用浏览器的本地时区。
6. 选择**发送到 Chat**。每次真实运行会创建一段独立对话。
7. 选择上一次仍在运行时怎样处理。重复报告会造成问题时，选择跳过或合并。
8. 保存自动化。
9. 手动运行一次，打开关联 Chat，阅读真实结果。

<a id="success-signal" />

## 检查结果

自动化页面应该显示已经保存的日程和下次运行时间。运行历史应链接到一段 Chat，
其中有可用简报或清楚的错误。

<a id="recovery" />

## 没有出现结果怎么办

先打开自动化运行历史：

- 被跳过或合并的运行应该说明为什么不需要新 Chat。
- 失败运行应该链接到已有的部分对话和 Agent 运行。
- 时间不对时，修正日程的时区理解。
- 结果质量不对时，通常需要改进指令、项目上下文或负责 Agent。

修复时先暂停自动化，重新手动测试成功后再恢复日程。
