<a id="completed-state" />

## 完成后的状态

完成本页后，客户简报项目会有一个主要项目工作区、少量精选资料、Library 中的持久简报、待评审 Issue 上的产物链接，以及一份负责人可以检查的工作区备份。

<a id="prerequisites" />

## 开始前

准备项目代码仓库或文件夹、项目运行应该得到的源笔记，以及最终产物要求。通过[工作区边界](/zh/reference/workspace-boundaries)判断内容应进入 Library、项目工作区、Agent 文件夹还是临时存储。

<a id="case-backed-steps" />

## 设置客户简报项目

1. 打开项目工作区设置，添加代码仓库或文件夹。如果项目运行应默认使用它，就设为主要工作区。
2. 把需要长期保存的源笔记加入 Library。Agent 操作说明、托管技能、缓存、凭据和草稿输出不能放进普通 Library 路径。
3. 只把本次简报需要的笔记附加为项目资料，并填写用途或说明，让 Agent 知道每项资料为什么相关。
4. 运行客户简报 Issue。确认 Agent 运行解析到项目工作区和精选资料引用，而不是组织中的全部文件。
5. 把接受后的简报保存到项目 Library 文件夹，并从待评审 Issue 链接为本次产物。
6. 从 Chat、Messenger 或 Issue 打开文件。受支持的预览和 Markdown 编辑可以留在 `Side Panel`，需要完整工作页面时选择 **Open in Library**。
7. 手动创建一份工作区备份，打开生成的版本并检查其中一个文件，确认它可以用于恢复。

Desktop 的文件打开和所在目录操作通过受校验的本地桥接完成。它们只是负责人的本地便利入口，不会扩大 Agent 工作区，也不会让浏览器部署打开本地应用。

<a id="success-signal" />

## 成功信号

项目只显示一个预期主要工作区和选中的起始资料。最终简报既能从 Library 打开，也能从评审 Issue 打开；Agent 运行记录了工作区上下文；手动备份则显示为一份可以检查的具体版本。

<a id="recovery" />

## 恢复

已经映射的组织文件夹丢失时，停止操作并恢复记录中的文件夹，或使用工作区备份。不要在映射路径创建空文件夹。如果 Markdown 编辑出现旧写入冲突，在比较最新服务端内容时保留本地草稿，再明确选择 **Keep mine** 或 **Use latest**。

恢复备份前，先检查所选版本，确认哪些文件会改变。Rudder 会创建恢复前安全备份。仍有未完成 Issue 依赖某个运行工作区时，不能归档；应先完成或迁移这些依赖。
