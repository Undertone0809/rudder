这个例子会把准备客户简报所需的文件交给 Agent，但不会暴露组织里的所有资料。

<a id="completed-state" />

## 这篇指南会设置什么

一个项目文件夹、少量来源资料、保存在 Library 的最终简报，以及一份可以检查的
备份。

<a id="prerequisites" />

## 开始前

准备 Agent 可以工作的仓库或文件夹、它需要的来源资料，以及你期待的结果。凭据
和无关的私人文件不要放进所选上下文。

<a id="case-backed-steps" />

## 设置项目

1. 打开项目，把代码仓库或文件夹添加为工作区。
2. 如果项目运行默认都应使用它，就设为主工作区。
3. 把需要长期保留的来源资料添加到 Library。
4. 只把这份简报需要的资料设为项目资源，并说明每份资料为什么相关。
5. 让 Agent 创建简报。打开运行记录，确认它使用了预期工作区和所选资料。
6. 把接受后的简报保存到项目的 Library 文件夹。
7. 从产生它的 Chat 或评审 Issue 链接过去。
8. 在侧边面板快速预览，或选择**在 Library 中打开**查看完整文件。
9. 手动创建工作区备份，并从保存版本中打开一个文件检查。

<a id="success-signal" />

## 检查结果

项目应该只显示一个预期主工作区，以及你亲自选择的资料。最终简报应该能从
Library 和产生它的任务打开，备份也应该是一份可以检查的具体版本。

<a id="recovery" />

## 文件缺失或版本过期怎么办

- 映射的组织文件夹消失时，恢复原目录或使用备份，不能新建空目录代替。
- 编辑 Markdown 时远端内容发生变化，应先比较本地草稿和最新版本，再选择保留
  哪一份。
- 恢复前先检查备份；Rudder 会先创建安全备份。
- 还有未完成 Issue 依赖某个运行工作区时，先关闭或移动任务再归档。

准确位置见[工作区位置参考](/zh/reference/workspace-boundaries)。
