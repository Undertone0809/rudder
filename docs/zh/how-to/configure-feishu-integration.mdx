<a id="completed-state" />

## 完成后的状态

完成本页后，一个 Rudder Agent 已连接并启用飞书或 Lark 集成。普通文本消息会进入绑定服务商的 Messenger 对话，Agent 能够回复，来源对话和 Agent 运行也会显示飞书来源证据。

<a id="prerequisites" />

## 开始前

先准备一个可以工作的 Agent，并确认你有权在目标飞书中国版或 Lark 国际版工作区授权或创建应用。如果希望安装人的外部身份自动绑定到 Rudder，还需要确保这个人是当前 Rudder 组织的有效成员。

下面用一个示意流程，把发布文案 Agent 连接到团队发布群。一项集成只属于一个组织和一个 Agent。

<a id="case-backed-steps" />

## 连接发布文案 Agent

1. 打开发布文案 Agent 详情页，再进入 **Integrations**。
2. 启动飞书设置，并按照实际工作区选择 **Feishu CN** 或 **Lark Global**。
3. Rudder 会打开服务商的应用授权页面，并填入安全的机器人建议名称。检查机器人、消息、表情回应、命令和接收事件等权限后，完成授权。
4. 回到 Rudder。设置页面会持续检查，直到凭据以组织机密保存，Agent 集成启用。
5. 在发布群里向机器人发送一条普通文本请求。群聊中需要明确提及机器人。
6. 打开 Messenger，找到带有 **Feishu** 来源标记的对话；再打开对应 Agent 运行，确认显示 **Source: Feishu**。
7. 想让下一条消息进入新的 Rudder 对话时，使用 `/new`。Agent 正在回复而你需要停止时，使用 `/stop`。

每日会话默认按 24 小时窗口滚动，而且只在窗口结束后的下一条外部消息到达时发生。安静的群聊不会在后台创建空会话。

<a id="success-signal" />

## 成功信号

发送人的消息和 Agent 回复都留在飞书或 Lark。Rudder 中绑定服务商的对话可以审计同一次交流，来源运行也带有飞书元数据。只有服务商明确拒绝富文本卡片时，Rudder 才会把同一正文降级为纯文本，避免在交付状态不确定时重复发送。

<a id="recovery" />

## 恢复

Rudder 重启后，如果授权仍停在等待状态，请重新开始设置，因为未完成的设置不会跨重启保留。如果打开了错误的服务商页面，重新开始并选择正确区域。发送人收到身份绑定说明时，先把飞书身份绑定到有效的 Rudder 组织成员，再次发送消息。

群消息被忽略时，先确认已经提及机器人。回复失败时，检查绑定服务商的对话、外发状态和 Agent 运行。如果要在 Rudder 本地继续同一上下文，只能创建这段飞书对话的分支；来源对话在 Rudder 中只读，分支之后也不会再向飞书回写。
