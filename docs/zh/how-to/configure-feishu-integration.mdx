这个连接让团队成员可以从飞书或 Lark 给 Rudder Agent 发消息。对话和相关 Agent
运行仍然可以在 Rudder 中查看。

<a id="completed-state" />

## 这篇指南会连接什么

把一个 Agent 连接到一个飞书中国版或 Lark 国际版机器人。文字消息会到达 Agent，
回复也会回到同一段外部对话。

<a id="prerequisites" />

## 开始前

你需要：

- 一个已经能工作的 Rudder Agent
- 在目标飞书或 Lark 工作区授权或创建应用的权限
- 设置人员在 Rudder 组织中的有效成员身份

<a id="case-backed-steps" />

## 连接并测试

1. 打开 Agent，再打开**集成**。
2. 选择**连接飞书 / Lark**。
3. 根据实际工作区选择**飞书中国版**或 **Lark 国际版**。
4. Rudder 会用建议的机器人名称打开服务商授权页面。检查消息、表情、命令和事件
   权限。
5. 完成授权并回到 Rudder，等待集成显示为已启用。
6. 给机器人发送一条纯文字测试请求。群聊中要明确提及机器人。
7. 打开 Messenger，找到带飞书来源标记的对话。
8. 打开对应 Agent 运行，确认来源是飞书。

下一条消息需要开始新 Rudder 对话时，使用 `/new`；需要停止正在生成的回复时，
使用 `/stop`。

<a id="success-signal" />

## 检查结果

发送者的消息和 Agent 回复应该同时出现在飞书或 Lark。Rudder Messenger 应该
显示同一段交流，并关联一条 Agent 运行。

<a id="recovery" />

## 常见问题

- **Rudder 重启后设置仍然等待中：**重新开始设置；未完成授权不会跨重启保留。
- **打开了错误的服务商页面：**重新设置并选择正确地区。
- **机器人要求发送者绑定身份：**把这个飞书身份连接到有效 Rudder 成员后重发。
- **群消息被忽略：**直接提及机器人。
- **回复失败：**打开外部来源对话和 Agent 运行查看错误。

来自服务商的对话在 Rudder 中只读。想只在本地继续、又不把后续回复发回飞书时，
从这段对话创建分支。
