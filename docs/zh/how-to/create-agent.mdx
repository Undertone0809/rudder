一类工作会反复出现，而且需要自己的职责或运行工具时，再创建新 Agent。只是偶尔
出现、又符合已有 Agent 职责的请求，直接交给现有 Agent。

<a id="completed-state" />

## 这篇指南会创建什么

示例会创建一个“发布文案” Agent，负责发布说明和公告文案。完成后，它会有一个
已经测试的运行工具，并且成功处理过一项小任务。

<a id="prerequisites" />

## 开始前

你需要一个组织，以及可以在 Rudder 所在电脑上运行的工具。使用本地工具时，请先
安装并登录对应命令行程序。

先确定 Agent 负责什么。“什么都帮忙”太宽泛；“根据确认过的产品事实起草并修改
公开发布文案”更容易分配和检查。

<a id="case-backed-steps" />

## 创建 Agent

1. 打开**智能体**，选择**新建智能体**。
2. 名称填写“发布文案”，职位可以写“发布沟通文案”。
3. 选择最接近的角色，并写一段简短的能力说明：

   ```text
   根据已经确认的产品事实起草和修改公开发布文案。
   遇到没有依据的主张时明确指出，没有人工评审时不发布。
   ```

4. 选择这个 Agent 使用的运行工具。设置模型或命令，然后选择**测试运行时链路**。
5. 只有这项职责已经确实需要时，才添加角色指令或技能。
6. 检查权限，并设置适合这类工作的月度预算。
7. 选择**创建智能体**。
8. 在 Chat 中让它写一份两段式公告草稿。第一次任务应小到可以马上判断。

<a id="success-signal" />

## 检查结果

打开 Agent，确认职责、能力说明、运行工具、权限、技能和预算。再打开测试运行，
确认预期运行工具确实返回了结果或清楚的阻塞原因。

<a id="recovery" />

## 无法工作怎么办

- **运行测试失败：**安装或登录命令行工具，修正命令后重新测试。
- **Agent 接受了不该做的任务：**缩小能力说明，并把任务要求写得更明确。
- **Agent 正在等待审批或已经暂停：**先处理审批或状态。
- **第一次任务风险太高：**换成短文案或只读检查，先证明设置可用。

详细排查见[配置 Agent 运行工具](/zh/how-to/configure-agent-runtime)。
