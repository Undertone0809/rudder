<a id="completed-state" />

## 完成后的状态

完成本页后，组织中会新增一名可辨认职责的 Agent。它有明确能力边界、已保存的运行环境配置，并且已经完成一次可以检查的低风险运行。

只有一类工作需要长期负责人时，才创建 Agent。一次性提示如果符合现有职责，不需要增加新成员。

<a id="prerequisites" />

## 开始前

你需要一个组织、创建 Agent 的权限、一项尚未由现有成员承担的重复职责，以及 Rudder 可以测试的运行环境。下面新建一名负责发布文案的 Agent，并用一份小公告完成首次验证。

<a id="case-backed-steps" />

## 创建发布文案 Agent

1. 打开 **Agents**，选择 **New Agent**。
2. 把 Agent 命名为“发布文案”，再填写能说明岗位的标题，例如“版本沟通文案”。
3. 选择最符合该 Agent 职责的角色。
4. 选择并配置运行环境，然后运行 **Test runtime chain**。
5. 使用本地运行环境时，填写用来限定职责和边界的提示模板。设置运行策略，并且只启用这项职责需要的可选技能。
6. 选择 **Create agent**。根据组织策略，新 Agent 也可能先进入待审批状态，不能立即运行。
7. 创建 Agent 后，打开 **Configuration**。把 **Capabilities** 写成验收边界，再检查同一页的 **Permissions**。
8. 打开 **Budget**，设置适合这项职责的每月限额。
9. 分配一条验收标准清楚的低风险发布公告 Issue，或在 Chat 中提出同样有边界的草稿请求。
10. 检查 Agent 运行、草稿产物、验证说明、可用的成本数据，以及任何阻塞。

<a id="success-signal" />

## 成功信号

Agent 详情显示预期职责、能力范围、权限、运行环境、技能和预算。低风险运行确实使用该运行环境，并在来源 Chat 或 Issue 留下产物，以及明确的完成或阻塞信号。

<a id="recovery" />

## 恢复

创建被阻止时，检查组织范围、创建 Agent 权限和运行环境测试。待审批、已暂停、已终止或访问已撤销的 Agent，都不能像普通有效 Agent 一样被唤醒。

首次运行接下了不该处理的工作时，收紧能力说明和分配上下文。无法启动时，按[配置 Agent 运行环境](/zh/how-to/configure-agent-runtime)修复，再重复低风险运行；验证通过前不要扩大任务范围。
