导出和导入可以迁移组织中受支持的结构，但它不是完整数据库备份。

<a id="completed-state" />

## 哪些内容可以迁移

当前软件包可以包括：

- 组织
- Agent
- 项目
- Issue
- 自动化
- 技能

目标、Library 文件、组织资源和已经保存的密钥不会包含在内。导入后的 Issue 也
不会保留目标关联。文件、密钥和目标关联需要另外迁移或重新创建。

<a id="prerequisites" />

## 开始前

你需要访问来源和目标 Rudder 实例，有足够磁盘空间保存软件包，并列出必须手动
重建的内容。替换凭据应保存在目标实例的密钥设置里，绝不能写进导出文件。

<a id="case-backed-steps" />

## 导出并导入

1. 打开来源组织的导出页面。
2. 选择要迁移的 Agent、项目、Issue、自动化和技能。
3. 开始导出，完成后下载软件包，并保留随包生成的 README 和清单。
4. 在目标实例打开导入页面，选择软件包。
5. 阅读预览，检查将创建的内容、缺少的依赖、名称冲突，以及仍要手动迁移的文件
   或密钥。
6. 选择创建新组织，填写显示名称和 Issue Key。
7. 通过目标实例的密钥设置添加必要凭据。
8. 应用刚才预览的方案。
9. 分别打开一个导入后的 Agent、项目、Issue、自动化和技能。确认无误后，再
   重建目标关联并迁移 Library 文件。

<a id="success-signal" />

## 检查导入副本

目标实例应该出现一个新组织，而不是来源组织的另一个地址。所选内容应能正常打开
并互相链接。软件包和导入内容中都不应出现凭据值。

<a id="recovery" />

## 预览或导入失败怎么办

- 把缺少的受支持依赖加入导出，或移除依赖它的内容。
- 目标已经使用同一 Issue Key 时，选择另一个 Key。
- 应用前先补齐缺少的密钥。
- 目标和文件等不支持内容应单独迁移。
- 应用失败后，先检查导入报告中已经创建了什么，再重试。

不要用直接修改数据库的方式绕过预览。
