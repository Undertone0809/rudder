<a id="completed-state" />

## 完成后的状态

完成本页后，选定的组织内容已经打包导出，并在导入前经过完整预览。当前软件包支持组织、Agent、项目、Issue、自动化和技能。导入副本拥有新的组织 UUID、规范路由键和 Issue Key。

<a id="prerequisites" />

## 开始前

你需要源实例和目标实例的看板访问权限、本地保存软件包的空间，以及一份只包含受支持实体的迁移清单。目标、Library 文件和组织资料不会包含在软件包中。替代用的机密和环境变量要另外准备。导出结果是带 `.rudder.yaml` 清单的可移植软件包，不是任意数据库转储，也不能泄露已保存机密。

导入的 Issue 不会保留目标关联，`goalId` 为 `null`。如果目标实例仍需要这些内容，应在导入后另行重建目标、目标关联、Library 文件和组织资料。

下面的示意案例把咨询团队的客户简报项目迁移到新的本地实例。

<a id="case-backed-steps" />

## 迁移客户简报项目

1. 打开源组织的导出页面，选择组织、相关 Agent、客户简报项目、其中的 Issue 和自动化，以及这些 Agent 需要的技能。
2. 启动导出任务。任务完成后下载软件包，把生成的清单和说明文件放在一起。
3. 打开目标实例的导入页面，选择这个软件包。
4. 应用之前先检查预览。核对选中的组织、Agent、项目、Issue、自动化和技能，以及冲突、机密或环境要求。另行确认导入后需要重建哪些目标、Library 文件和组织资料。
5. 选择导入为新组织。填写新的显示名称，并单独检查建议的 Issue Key。如果 Key 冲突，应明确改用另一个 Key，不要为了绕过冲突而改掉导入名称。
6. 通过目标实例的机密设置补充必要凭据。
7. 按已经预览的方案执行导入。
8. 分别打开一个导入的 Agent、项目、Issue、自动化和技能。确认受支持的关联都指向新组织内部，并在重建目标关联前确认导入的 Issue 没有目标关联。

<a id="success-signal" />

## 成功信号

目标实例显示全新的组织身份，没有复用源 UUID 或历史路由别名。选中的 Agent、项目、Issue、自动化和技能都已出现；导入 Issue 的 `goalId` 为 `null`；软件包预览和导入内容中也没有任何凭据值。

<a id="recovery" />

## 恢复

预览报告缺少受支持依赖时，回到导出流程补上，或从导入范围中移除依赖它的实体。目标、目标关联、Library 文件和组织资料需要在软件包流程之外重建。Issue Key 冲突时，明确选择替代值。缺少机密时，先停止应用，通过目标实例的机密入口准备好再继续。

不要跳过预览直接写数据库。如果应用失败，保留软件包和预览证据，按导入报告检查已经写入目标实例的实体，再解决明确指出的冲突后重试。
