Rudder 插件是由技能、MCP 服务端、应用或它们的组合构成的能力包。你可以浏览
Rudder 精选目录，输入 `skills add` 兼容的公开 GitHub 来源，或导入 Codex 插件目录。
所有路径都会在安装前展示不可变的兼容性预览。

<a id="completed-state" />

## 你将完成什么

打开 **Hub**，发现或导入插件，预览 Rudder 可以使用的内容，把它安装到组织，并完成
必要的 Agent 或 MCP 设置。

<a id="prerequisites" />

## 开始前

准备一个包含 `.codex-plugin/plugin.json` 以及至少一个技能或受支持 MCP 定义的
目录。不要把凭据写入清单或 MCP 配置；请使用环境变量引用，并在 Rudder 的
托管 MCP 设置中完成认证。

<a id="case-backed-steps" />

## 安装和设置

1. 在主导航栏中选择 **Hub**，打开 **Plugins**。
2. 打开一个精选插件，使用 **URL Import** 输入
   `coreyhaines31/marketingskills` 这类公开来源，或选择 **Import** 后再选
   **Plugin folder** / **Plugin ZIP**。也可以添加 **Local marketplace** 或
   **Pinned GitHub marketplace**。
3. 在预览中检查软件包身份、摘要、技能、MCP 定义、应用引用、技能中的可执行文件，
   以及浏览器扩展、定时任务模板和钩子等不支持的能力。检查
   过程不会执行任何内容。
4. 如果技能与现有组织技能冲突，显式选择保留现有版本、替换，或重命名后同时安装。
   然后把软件包安装到当前组织。
5. 对于技能，选择 **Add to Agent**，再选择可以使用它的 Agent。
6. 对于 MCP 定义，选择 **Set up**，然后在托管 MCP 设置中继续认证、启用和 Agent 访问配置。
7. 本地应用可以从 **Hub > Plugins** 直接打开。Codex `.app.json` 别名会被保留，但不是可执行的 Rudder 本地应用。
8. 如果已启用的托管 MCP 连接提供 `HTML` 界面资源，可以从 MCP 组件中打开。
   Rudder 会在禁止网络访问的沙箱中渲染。

对于精选和链接来源，Rudder 会把最新稳定语义化发布版本或默认分支最新提交解析为
完整 `commit SHA`。预览和安装使用同一份不可变快照。Rudder 不会执行 `npx`、
软件包钩子或技能脚本。市场策略只作为来源信息保留；即使条目声明
`INSTALLED_BY_DEFAULT`，也仍要求显式安装，不会静默安装。

<a id="success-signal" />

## 检查结果

插件详情应显示 **Ready** 或 **Setup required**，并展示准确版本、来源、摘要和组件状态。
软件包中的技能应成为只读、由软件包管理的组织技能，而且只会分配给
所选 Agent。MCP 连接在正常设置完成前保持为已禁用的草稿状态。

当前组织至少有一个可用的已安装能力后，可以使用 **Try in Chat**。如果要
独立编辑某个技能，选择 **Customize**。Rudder 会创建带来源信息的本地托管组织技能
副本，之后的插件生命周期操作不会修改或删除它。

<a id="recovery" />

## 更新或回滚

打开新版本的详情预览后再选择 **Update**。Rudder 会展示新旧执行面；如果更新新增或
改变可执行技能或 MCP 访问，必须显式确认权限扩张。之后 Rudder 会先准备新版本的
组件投影，再切换当前安装。如果准备失败，现有版本继续生效，这次预览也可以重试。

更新成功后，可以选择 **Roll back** 重新启用保留的上一份不可变软件包。回滚不会
改写任何一个软件包快照。

应用构建器产生新的本地应用版本时，**Hub** 会显示 **Update available**。当前版本会继续运行，
直到用户在插件详情中选择 **Apply update**。

## 禁用或卸载

禁用插件会阻止其能力进入新的工作，但不会删除软件包、外部连接、应用源码或
应用数据。重新启用会恢复之前的技能分配。

卸载会移除软件包拥有的技能投影和当前安装记录，不会删除用户目标、自动化、文档、
外部 MCP 连接、本地应用源码或业务数据。之后仍可重新预览并安装该软件包。
