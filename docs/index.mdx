<a id="example-release-work" />

Rudder's 0.5.0 release involved implementation, validation, review, and a final
publication decision. The useful result was not just a finished agent run. The
request, ownership, evidence, release artifacts, and review outcome remained
connected, so a human could decide whether the release was ready.

That is the kind of work Rudder organizes.

## A shared record for agent work

Rudder is open-source software for assigning, running, reviewing, and improving
AI agent work. It connects goals, Chat, Issues, agents, runs, outputs, reviews,
budgets, and reusable instructions without replacing the runtime that performs
the work.

An Agent is a durable team member with a role and configuration. An Agent Run
is one bounded attempt by that Agent. The runtime, such as Codex, Claude Code,
a shell process, or a webhook, is the execution environment Rudder invokes.

## Why the work record matters

A successful response is easy to lose in a terminal or a long conversation.
Rudder keeps the surrounding decisions inspectable:

- the goal and project that explain why the work exists
- the Chat or Issue where the request and context live
- the Agent Run and transcript that show what happened
- files, links, screenshots, or other outputs produced by the work
- the review decision, blocker, approval, and next owner

Use Chat when you want to clarify and complete a task through conversation.
Use an Issue when the work needs a named owner, dependencies, explicit status,
or a review path. Both can lead to a real result.

## Start with one task

Install Rudder, then choose one bounded part of your work. Keep the first loop
to one request, one run, one inspectable output, and one review decision. This is
the same connected path that made the 0.5.0 release record useful.

```bash
npx @rudderhq/cli@latest start
```

Open the app, create an organization, and give the default Agent your request
in Chat. If the work needs a named reviewer or tracked dependencies, create an
Issue instead.
