Agents that think, build, play, and learn from real work.

Rudder turns goals, issues, agent runs, reviews, and feedback into a work loop
for agent teams. It gives humans and agents a shared operating structure for
assigning work, running agents, reviewing outputs, controlling spend, and
preserving the lessons that should make the next run better.

In practice, you give an Agent a task, watch it work, inspect the files or
answers it produces, and decide what happens next. Rudder uses your existing
runtime—such as Codex, Claude Code, a local command, or a webhook—rather than
replacing it.

## What Rudder helps you do

- **Start in Chat.** Ask for a draft, a code change, research, or any other
  concrete result. Continue the conversation until the result is useful.
- **Track larger tasks as Issues.** Add an owner, status, dependencies, and a
  reviewer when a conversation is no longer enough.
- **See what the agent actually did.** Each run keeps its result, activity, and
  available logs together.
- **Keep useful output.** Files, links, screenshots, and reports stay connected
  to the task that produced them.
- **Control recurring work.** Reuse skills, schedule automations, and keep an
  eye on cost and failures.

## A simple example

Imagine asking an agent to improve your onboarding page.

1. You describe the result you want in Chat.
2. Rudder starts the agent with the runtime and project you selected.
3. You follow its progress and open the changed file or preview.
4. You ask for changes or accept the result.
5. If the work grows, you turn it into an Issue so ownership and review remain
   clear.

The value is simple: you do not have to reconstruct the task later from a
terminal, a long chat, and a folder full of unexplained files.

## Start in three steps

1. Install and open Rudder.
2. Create an organization, your team workspace, and connect your first agent runtime.
3. Ask the agent for one small, real result.

```bash
npx @rudderhq/cli@latest start
```
