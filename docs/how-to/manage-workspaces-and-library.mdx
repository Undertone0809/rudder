Use Workspaces and Library to keep agent context and outputs findable. The goal is simple: a future run should know where to look, and a human should know which files are durable.

## Choose the right location

| Content | Put it here |
| --- | --- |
| Project repository work | Project workspace |
| Durable reports, plans, screenshots, and handoffs | Project folder in Library |
| Shared references | Library files |
| Curated run context | Project Context resources |
| Agent-private memory and skills | Agent home |
| Scratch files | `/tmp` or the system temp directory |

## Add Library files

Use Library for files that should remain part of the organization record. Library files can be referenced from issues, resources, and agent context.

Good Library files include:

- research briefs
- decision notes
- source documents
- reusable checklists
- project reports
- handoff packets

Avoid putting temporary screenshots, local caches, or generated scratch files in Library unless they are part of the final evidence.

## Attach project resources

Project Context resources are the curated starting context for project-linked runs. Attach the files, URLs, repositories, or connector objects the agent should see by default.

Do not attach every organization resource. Keep the default context small enough that the agent can use it.

## Use project folders for durable output

Rudder creates a Library folder for each project. Put durable project work there. Agents may add natural subfolders such as `research/`, `screenshots/`, `handoff/`, or `evals/`.

Use issue comments or review notes to point reviewers to the relevant file.

## Inspect and edit files beside your work

Open a Library reference from Chat, Messenger, or an issue to inspect it in the
Side Panel. The panel keeps the current work surface visible and supports inline
previews for files such as PDFs.

For Markdown files:

1. Edit directly in the Side Panel and watch the save state.
2. If Rudder reports a stale-write conflict, review the preserved local draft.
3. Choose **Keep mine** to retry your draft against the latest version, or
   **Use latest** to replace it with the current server version.

Do not close the conflict as if the save succeeded. The draft remains local
until a guarded save succeeds or you explicitly choose the latest version.

On Desktop, use the file **Open** menu to open it in the system default app or a
detected IDE, reveal it in the file browser, open its containing directory in a
terminal, or move to the full Library surface with **Open in Library**.

## Use backups deliberately

Workspace backups help recover organization workspace state. Treat them as operator tools:

- browse backup versions before restoring
- restore only when you understand what will change
- delete old backups when they are no longer useful
- download a backup when you need to inspect or preserve it outside Rudder
