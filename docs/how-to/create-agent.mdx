Create another Agent when a recurring kind of work needs its own role or
runtime. For a one-off request that fits an Agent you already have, use the
existing Agent.

<a id="completed-state" />

## What you will create

This example creates a `Launch Writer` that drafts release and announcement
copy. At the end, it will have a tested runtime and one small successful task.

<a id="prerequisites" />

## Before you start

You need an organization and a runtime that works on the Rudder host. For a
local runtime, install and sign in to its CLI first.

Decide what the Agent should own. “Help with anything” is too broad; “Draft and
revise public launch copy” is easier to assign and review.

<a id="case-backed-steps" />

## Create the Agent

1. Open **Agents** and choose **New Agent**.
2. Enter `Launch Writer` as the name and use a title such as `Release
   Communications Writer`.
3. Choose the closest role and write a short capability statement:

   ```text
   Drafts and revises public launch copy from approved product facts.
   Flags unsupported claims and does not publish without human review.
   ```

4. Choose the runtime this Agent will use. Configure the model or command, then
   run **Test runtime chain**.
5. Add role instructions or Skills only when they are already useful for this
   responsibility.
6. Review permissions and set a monthly budget appropriate for the work.
7. Choose **Create agent**.
8. In Chat, ask for a two-paragraph announcement draft. Keep the first task
   small enough to judge immediately.

<a id="success-signal" />

## Check the result

Open the Agent and confirm its role, capability statement, runtime, permissions,
Skills, and budget. Then open the test Run and verify that the intended runtime
produced an answer or a clear blocker.

<a id="recovery" />

## If it does not work

- **The runtime test fails:** install or sign in to the CLI, correct the command,
  and test again.
- **The Agent accepts the wrong work:** narrow the capability statement and the
  task instructions.
- **The Agent is pending or paused:** resolve the approval or status before
  trying to run it.
- **The first task is too risky:** replace it with a short draft or read-only
  check until the setup is proven.

For detailed runtime troubleshooting, see [Configure an Agent
runtime](/how-to/configure-agent-runtime).
