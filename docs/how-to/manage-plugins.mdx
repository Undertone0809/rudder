Plugins run installed code. Use packages you trust and read what they request
before activation.

<a id="completed-state" />

## What you will do

Install one Plugin, review its capabilities and settings, confirm its worker is
healthy, and test one real action.

<a id="prerequisites" />

## Before you start

Prepare the Plugin source, its setup instructions, any external service account,
and a known previous version or uninstall path. Do not put credentials inside
the package or logs.

<a id="case-backed-steps" />

## Install and test

1. Open **Plugin Manager** and choose the supported package or source.
2. Review the publisher, version, worker and interface code, external services,
   requested capabilities, tools, jobs, and webhooks.
3. Enter required settings. Store credentials only in the provided secret
   fields.
4. Install and activate the Plugin.
5. Check worker health and startup logs before using its interface.
6. Trigger one small test action.
7. Open the Plugin's job record, logs, and state to confirm what happened.
8. Before updating, review version changes, new capabilities, configuration
   changes, and migration notes.

<a id="success-signal" />

## Check the result

Plugin Manager should show the expected version and a healthy worker. The test
action should appear under that Plugin with readable status and logs.

<a id="recovery" />

## If activation or an update fails

- Leave a failed Plugin inactive while you fix its settings or package.
- Read the named manifest, capability, worker, or connection error.
- Stop dependent jobs and webhooks before uninstalling.
- Return to the last reviewed package when your install source supports it, or
  uninstall through Plugin Manager.

Uninstalling a Plugin should remove its workers and own state, not core Rudder
Issues, Runs, reviews, approvals, or budgets.
