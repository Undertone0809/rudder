Use export and import when you need to move organization knowledge between Rudder instances or preserve a copy of the operating record.

## What export is for

Export is for organization portability. It should preserve the knowledge and structure needed to understand the organization later.

Depending on the current product surface, an export may include organization settings, goals, projects, agents, issues, resources, Library metadata, and related records. Treat it as organization data, not as a full machine backup.

## Before export

Check:

- the organization is the one you intend to move
- important work is closed or named as in progress
- durable files are in Library or project workspaces
- sensitive data is understood before sharing the archive

## Import safely

Import should be previewable and scoped. Before applying an import, inspect what it will create or update.

Use the preview to check:

- target organization
- object counts
- conflicts or missing references
- settings that may change behavior
- resources or files that need follow-up

Do not apply an import if the preview does not match the organization you expect.

### Check the imported organization identity

When importing into a new organization, review the new organization name and
Issue Key separately. Changing the proposed Issue Key does not rename the
imported organization. The target Rudder instance rejects an Issue Key that
conflicts with another organization's current URL, current Issue Key, or
historical Issue Key, so resolve the conflict in the preview before applying.

A new-organization import receives a fresh internal identity and stable URL.
Historical Issue Key aliases from the source instance are not copied to the new
organization.

## After import

Open the imported organization and inspect:

- goals and projects
- agents and runtime settings
- issues and review state
- the new Issue Key and readable issue references
- Library files and resources
- automations or integrations that may need credentials

External credentials and local runtime paths may need to be configured again on the target machine.
