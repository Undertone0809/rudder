Export/import moves the supported structure of an organization. It is not a
full database backup.

<a id="completed-state" />

## What can move

The current package can include:

- the organization
- Agents
- projects
- Issues
- Automations
- Skills

Goals, Library files, organization resources, and stored secrets are not
included. Imported Issues do not keep their Goal links. Plan to move files and
recreate secrets and Goal links separately.

<a id="prerequisites" />

## Before you start

You need access to both Rudder instances, enough disk space for the package, and
a list of what must be recreated. Store replacement credentials in the
destination's secret controls, never inside the export file.

<a id="case-backed-steps" />

## Export and import

1. Open the source organization's export page.
2. Select the Agents, projects, Issues, Automations, and Skills you want.
3. Start the export, wait for it to finish, and download the package. Keep its
   generated README and manifest with it.
4. Open the import page on the destination and select the package.
5. Read the preview. Check what will be created, any missing dependencies or
   name collisions, and which files or secrets still need manual work.
6. Choose to create a new organization and enter its display name and Issue
   Key.
7. Add required secrets through the destination's secret settings.
8. Apply the previewed plan.
9. Open one imported Agent, project, Issue, Automation, and Skill. Recreate Goal
   links and move Library files only after confirming the import.

<a id="success-signal" />

## Check the imported copy

The destination should contain a new organization, not a second route to the
source organization. Selected entities should open and link to one another.
No credential value should appear in the package or imported content.

<a id="recovery" />

## If the preview or import fails

- Add a supported dependency to the export or remove the item that requires it.
- Choose a different Issue Key when the destination already uses it.
- Add missing secrets before applying the import.
- Move unsupported Goals and files separately.
- If applying fails, inspect what the import reports as already created before
  retrying.

Do not skip the preview with direct database writes.
