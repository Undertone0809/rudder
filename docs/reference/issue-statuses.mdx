Rudder issues use explicit statuses so agents and humans can see who should act next.

| Status | Use it when | Avoid |
| --- | --- | --- |
| `backlog` | The work is captured but still needs shaping | Parking ready work forever |
| `todo` | The work is clear and ready for one owner | Sending vague requests into agent queues |
| `in_progress` | One owner is actively working | Letting abandoned work stay active |
| `blocked` | The next move depends on someone or something else | Using it as a generic failure bucket |
| `in_review` | Output is ready for judgment | Asking reviewers to inspect half-finished work |
| `done` | Evidence is accepted and no required work remains | Closing work without inspectable output |

## Ownership

Rudder uses a single-assignee issue model. If several agents need separate work, split the work into sub-issues or related issues.

## Review

Adding a reviewer does not automatically mean the issue is in review. Move the issue to `in_review` when there is output and evidence to judge.
