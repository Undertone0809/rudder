Local runtimes need access to files, credentials, skills, and tools. Rudder should make those boundaries visible rather than hiding them inside a prompt or shell command.

## Managed runtime homes

Agents use managed homes for runtime state, instructions, skills, and local files that belong to that agent. This keeps agent-private state separate from shared Library files and project workspaces.

## Operator home bridges

Some local tools need access to credentials or config already present on the operator's machine. Use those bridges deliberately. They are useful for local trusted development, but they should not be treated as shared organization data.

## Skills and credentials

Skills are reusable operating instructions. Credentials are sensitive local or remote access material. Do not mix them.

When a runtime needs credentials, prefer the configured runtime path or local provider setup that already owns those credentials. Avoid copying secrets into docs, prompts, Library files, or issue comments.

## Built-in Browser boundary

Rudder Desktop's [Built-in Browser](/concepts/built-in-browser) uses one persistent website session per operating-system user and local Rudder instance. Cookies and site data are intentionally shared across organizations and between operator and supported agent tabs on that instance. Treat a website sign-in as instance-shared local state, not organization-scoped data.

Agent control remains isolated by organization, agent, run, and tab. Shared cookies do not let one run inspect or operate another run's tab. Agents receive only bounded browser actions; they do not receive raw cookies, passwords, arbitrary JavaScript execution, or unrestricted browser control.

Disabling agent Browser access preserves the operator's tabs and saved website data. Clearing browsing data removes the shared instance session. Choosing the system browser for ordinary links changes link routing only.

## Platform differences

File behavior differs across macOS, Linux, and Windows. A runtime setup that works through symlinks or Unix permissions on one platform may need a safe copy or another fallback on another platform.

When runtime setup fails, check the visible runtime readiness state and error message first. Then inspect whether the problem is missing CLI, missing permissions, missing credentials, unwritable workspace, or a platform-specific file operation.

Built-in Browser cookie import is currently macOS-only and supports local Google Chrome, Microsoft Edge, and Brave Browser profiles. It imports supported cookies after operator confirmation; it does not import passwords. Windows and Linux Browser cookie import is not supported.
