Automation output routing decides where people inspect the result.

New custom automations default to chat output. Tracked issue output remains an explicit alternative when the repeated work needs issue lifecycle structure.

## Choose issue output

Use issue output when the result needs:

- assignment
- status tracking
- review
- artifacts or files
- follow-up work
- durable close-out evidence

Issue output creates an execution issue and enters the normal assignment, run, review, and close-out lifecycle. Choose it for the structure itself, not merely because the work is important, expensive, or long-running. A governed team policy can still require issue fields.

## Choose chat output

Use chat output when people should receive and continue the result through a conversation rather than a structured issue lifecycle.

Good examples:

- iterative reports that invite follow-up questions
- status checks that operators want to continue in context
- informational replies delivered as a conversation
- analysis that benefits from conversational refinement

Chat output keeps the audit trail on the automation run and the chat transcript.

Each real execution gets a separate Messenger conversation linked to its automation run. It does not reuse an arbitrary existing human Chat as the destination for all future runs.

Skipped or coalesced runs do not create empty conversations. If a chat-output execution fails, Rudder leaves visible partial or fallback evidence instead of silently creating an empty unread thread.

## If unsure

Choose issue output for explicit assignment, status, or lifecycle management. Choose chat output for conversation-driven delivery and follow-up. Importance and run length alone do not decide the mode.
