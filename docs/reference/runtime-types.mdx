Rudder coordinates agent work. Runtimes do the work.

## Supported shapes

| Runtime shape | Use it for |
| --- | --- |
| Local CLI | Local coding agents such as Codex, Claude Code, Cursor, Gemini, OpenCode, or similar tools |
| Shell process | Custom local commands that can run as an agent process |
| HTTP webhook | External services that receive a request and report back |
| Gateway runtime | Gateway-backed agent systems managed outside the local app |

The exact runtime options available in your app depend on installed packages, configured providers, and local machine setup.

## Managed Rudder tools

Managed control tools are adapter capabilities, not a feature shared automatically by every runtime shape.

| Runtime | Managed tool path | Built-in Browser in Desktop `local_trusted` |
| --- | --- | --- |
| Codex local | Rudder-managed MCP configuration | Supported when enabled |
| Claude Code local | Rudder-managed MCP configuration | Supported when enabled |
| OpenCode local | Rudder-managed MCP configuration | Supported when enabled |
| Pi local | Rudder-managed native tool bridge | Supported when enabled |
| Other supported local runtime | Runtime-specific; consult bundled `rudder-docs` for the CLI fallback only when exact command guidance is needed | Not promised |
| Shell, webhook, gateway, or remote runtime | No local managed tool path is promised | Not promised |

Rudder prepares the managed path automatically for each eligible run. It is first-party runtime infrastructure, not a custom integration or an MCP server that operators configure manually. See [Built-in Browser](/concepts/built-in-browser) for its shared website-session and isolated tab-control boundaries.

## What runtime configuration controls

Runtime configuration controls how Rudder invokes the agent:

- command or endpoint
- working directory
- model or provider options
- environment variables
- instruction and context loading
- result parsing and reporting

## Readiness

Before relying on a runtime, test it from the agent configuration screen. A ready runtime should be invokable, able to receive the intended context, and able to report a result that Rudder can inspect.
