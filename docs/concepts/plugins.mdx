<a id="definition" />

## What a Plugin can add

A Plugin is an optional package installed by the Rudder host. Depending on the
package, it can add:

- tools an Agent can use
- connections to another service
- background jobs and webhooks
- project panels or other interface sections
- Plugin-specific settings and stored state

Rudder shows the Plugin's version, configuration, worker status, logs, jobs,
webhooks, and requested host capabilities.

<a id="case" />

## Example: connect a CRM

A CRM Plugin adds an account panel to a project and runs a scheduled sync. If
the sync fails, its job and logs remain under that Plugin. The Plugin can link
an account to Rudder work, but it does not invent a new Issue status or bypass
normal approvals.

<a id="when-useful" />

## Use a Plugin for an optional edge

Plugins fit integrations and specialized tools that not every Rudder user
needs. Goals, Chat, Issues, Runs, reviews, budgets, and workspaces remain built
in because they organize the core work.

<a id="operating-boundaries" />

## Install only code you trust

Plugins contain worker or interface code that runs as part of the installation.
Capability checks limit how a Plugin talks to Rudder, but they do not turn an
untrusted package into a safe sandbox.

Before activation, review the source, publisher, version, requested
capabilities, external services, configuration, and update notes. Uninstalling
a Plugin stops its workers and removes its own state; it should not delete core
Issues, Runs, approvals, or budgets.

Follow [Manage Plugins](/how-to/manage-plugins) to install and test one.
