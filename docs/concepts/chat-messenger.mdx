Chat and Messenger are one communication system with two jobs: Chat is a conversation-driven way to move tasks from request to result, and Messenger brings attention back to the right chat, issue, run, or decision.

Use Chat when you prefer to work through an ongoing conversation. Use Messenger when something anywhere in the work system needs your attention.

![Messenger attention surface](../images/messenger-approvals.png)

## How they fit together

| Surface | Use it for | Move forward by |
| --- | --- | --- |
| Chat | Clarifying, executing, refining, and completing tasks through conversation | Continue in Chat, or create/link an issue when structured coordination helps |
| Messenger | Replies, issue threads, failed runs, blockers, reviews, budget alerts, and decisions | Returning to the linked issue, run, or thread with a clear next action |

The boundary is simple: Chat moves work forward. Messenger keeps active work from losing human attention.

## When to add issue structure

Chat and issues are parallel task workflows, not consecutive stages. Create or link an issue when you want any of the following structure:

- one owner to execute the next step
- agent runtime budget
- review or approval
- a recovery point after failure or blocking
- a durable history the team can inspect later

You may still continue the task in Chat. Creating an issue adds structured coordination; it does not make the task more real. Team policy may require issue fields for governed workflows.

![Chat issue proposal](../images/chat-create-issue-proposal.png)

## What Messenger should bring back

Messenger answers one operator question:

> What needs my attention right now, and which native work object does it belong to?

Use it to move from signal back to action:

| Attention signal | Durable next step |
| --- | --- |
| Agent asks a question | Reply, then keep the decision in the originating Chat or linked issue |
| Run fails | Open the linked Chat, issue, or run and decide recovery |
| Work is blocked | Name the missing input or owner |
| Review is waiting | Approve, request changes, or mark blocked |
| Chat proposes an issue | Accept, edit, or reject the optional structured work item |

Messenger should not become a separate task system. Return the next step to the native Chat, issue, run, review, or approval that owns it.

## Anti-patterns

Avoid using Chat or Messenger as:

- a hidden backlog
- a replacement for the native state of its chats, issues, runs, reviews, or approvals
- a place where execution evidence has no durable source object
- the only record of a review decision
- a generic chat app disconnected from Rudder work
