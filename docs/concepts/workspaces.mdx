Rudder uses a few file locations because source material, working files, and
finished output need different treatment.

<a id="definition" />

## Where files belong

| Location | Put this here |
| --- | --- |
| Library | Files your team or future Agents should be able to find again |
| Project resources | The small set of Library or external material a project should provide to its Runs |
| Project workspace | The repository or folder where project work happens |
| Run workspace | The exact folder or branch used by one Agent Run |
| Agent home | Managed instructions, memory, and Skill state for one Agent |
| Workspace backup | A saved organization workspace you can inspect or restore |

Project resources are a curated starting set, not permission to read every file
in the organization.

<a id="case" />

## Example: prepare a client brief

Keep the client's approved source notes in Library and add only the relevant
ones to the project. Let the Agent work in the project repository. Save the
accepted brief back to Library and link it from the Chat or review Issue.

The next Agent can now find the approved result without inheriting every scratch
file from the first attempt.

<a id="when-useful" />

## A simple rule

- **Input you want to reuse:** Library or project resources
- **Files the Agent may change:** project or Run workspace
- **Final result:** keep it linked to its Chat, Issue, Run, or project
- **Temporary scratch files:** do not promote them to Library by default

On a standard local Desktop setup, organization files live in a mapped folder
under `~/Documents/Rudder`.

<a id="operating-boundaries" />

## Safe recovery

Agent instructions, managed Skills, credentials, and cache folders are not
ordinary Library files. If a mapped organization folder disappears, restore it
or use a backup; do not create an empty replacement and assume the data is
safe.

Inspect a backup before restoring it. Rudder creates a safety backup first.
Open work can prevent a Run workspace from being archived until its dependent
Issues are closed or moved.

For exact locations and platform behavior, see [Workspace
boundaries](/reference/workspace-boundaries).
