Rudder is the operating layer around agent work. It does not replace the runtime. It records the operating state that lets a human understand what agents are doing and when they need help.

## What the operating layer tracks

The operating layer brings several kinds of evidence into one product surface:

- approvals for governed actions
- budgets and cost events
- activity logs for product mutations
- run summaries and raw evidence
- dashboard health
- Calendar history
- inbox attention for humans

These surfaces should help an operator answer simple questions: what moved, what failed, what cost money, what needs review, and what needs a decision.

## Approvals

Approvals are for actions that should not happen silently. Rudder keeps the requested action, state, decision, and application evidence together so the team can see what was allowed and why.

## Budgets and cost

Budgets make autonomy visible. Agents can run automatically, but hidden spend should not accumulate without a control surface.

Use budgets and cost views to see:

- where agent work is spending tokens or money
- which runs are expensive
- when a budget limit should stop further work

## Activity

Activity logs show product mutations such as issue updates, review decisions, comments, approvals, and run events. They are not a replacement for the issue or run detail page. They are the audit trail across surfaces.

## Run intelligence

Run intelligence summarizes execution without hiding the raw evidence. A summary is useful for scanning, but the transcript, result, logs, and linked artifacts still matter when a run needs review.

Organization run lists use a bounded summary by default. Each row keeps the
identity, status, timing, agent and runtime, target, outcome or error, usage,
cost, skill evidence, and log availability needed for scanning without loading
the complete diagnostic payload for every run.

Open a single run when you need its full result, context, transcript, events, or
logs. Events, logs, and transcript entries load in bounded pages so a large run
does not turn the organization list into one unbounded response. Official CLI
list commands follow the same summary default; use `--full` only when a
compatibility export needs the complete list shape.

## Dashboard, Calendar, and Inbox

The dashboard gives an organization-level readout. Calendar shows work over time. Inbox focuses human attention.

Use them together:

- Dashboard for current operating health
- Calendar for historical run and work patterns
- Inbox for items that need a human response
