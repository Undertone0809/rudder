# Side Chat

## Summary

Add an ephemeral Side Chat workflow that branches from an assistant reply,
opens as an interactive Side Panel target, and leaves the parent Chat draft,
scroll, transcript, and active generation untouched. A Side Chat is hidden from
normal Chat and Messenger lists until the operator explicitly moves it into
Messenger.

The revised lifecycle decision is: there is no Done action. Closing a Side Chat
tab discards an unsent provisional draft or destroys its hidden persisted chat.
Expiry makes it read-only; the Side Chat tab menu's `Move to Messenger` action
preserves the same id and opens it as a normal durable Messenger Chat. Every
Side Panel tab has a compact context-menu `Close` action while retaining the
existing hover/focus close affordance and close-tab keyboard shortcut.

## Product Logic Alignment

Affected contracts are `CHAT.LIFECYCLE.001`, `CHAT.FORK.001`,
`CHAT.SIDE.PANEL.001`, `MESSENGER.ATTENTION.001`, and the dedicated
`CHAT.SIDE.CHAT.001` lifecycle contract added after explicit user approval on
2026-07-20. The registry now records the implemented Side Chat entry points,
hidden lifecycle, promotion, ownership, evidence, and terminal states.

## Scope

In scope:

- `/side` composer command and an assistant-message `Open side chat` action.
- `Side Chat` in the Side Panel empty/add-target surface.
- A provisional client draft; the server record is created on first Send.
- Exact source conversation and assistant-message anchoring.
- An interactive Side Panel transcript and composer using the normal Chat
  runtime path.
- A two-hour send window refreshed by persisted Side Chat messages.
- Explicit tab close, which destroys the provisional or persisted temporary
  Side Chat and cancels a live generation when necessary.
- Expiry, which makes the Side Chat automatically non-editable.
- A context menu on every Side Panel tab, opened by right-click,
  `Shift+F10`/Menu, or touch long-press, with `Close` for every target.
- `Move to Messenger` on the Side Chat tab menu, preserving the same
  conversation id and placing it in an existing source group when one exists;
  otherwise it becomes an ungrouped Messenger Chat.
- Focusable disabled Move states with state-specific explanatory tooltips for
  a provisional draft, lifecycle loading, and expired/unavailable Side Chats.
- Organization and operator ownership checks, idempotent creation, activity
  logging, and visibility filtering.
- Automated server/UI/E2E coverage and rendered browser verification.

Out of scope:

- A discoverable Side Chat history/archive.
- Reopening an expired Side Chat for mutation.
- Cross-device restoration of an unsent provisional draft.

## Design Notes

- The UI label is `Side Chat`; the persisted kind is `side_chat`.
- Creation is idempotent by organization, owner, and client mutation id.
- Source context is copied through the anchor, but copied messages do not gain
  new run/output ownership.
- Closing destroys temporary data; expiry preserves the record only until the
  operator closes the Side Chat tab.
- Promotion never creates a group implicitly. It joins the source's existing
  group when one exists; otherwise the promoted Chat is simply listed.
- Opening a context menu for a non-active tab does not switch the panel body or
  active tab. Disabled Move items use `aria-disabled` rather than removal or an
  unfocusable disabled primitive so keyboard users can read the tooltip.
- Promotion retains the server contract `POST /api/chats/:id/side-chat/keep`
  and lifecycle state `kept`; only the operator-facing action is renamed.
- The in-progress Chat service extraction already present in the working tree
  is unrelated and must not be staged with this feature.

## Success Criteria

- All three entry points open the same provisional Side Chat workflow.
- First Send creates exactly one hidden Side Chat and starts a real agent run.
- Parent Chat composer value, scroll position, transcript, and generation are
  unchanged.
- Hidden Side Chats do not appear in Chat lists, Messenger lists, recent chats,
  search, or custom groups.
- Expired Side Chats reject sends with zero side effects.
- Closing destroys the temporary Side Chat; there is no Done action.
- `Move to Messenger` preserves the conversation id and makes it durable and
  visible with correct group placement, closes the source tab, then renders it
  with the normal Chat UI.
- Promotion failure leaves the Side Chat tab open and surfaces a retryable
  error. Every tab remains closable from its menu, inline close affordance, and
  platform close-tab shortcut without breaking drag reorder.
