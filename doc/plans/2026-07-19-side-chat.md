# Side Chat

## Summary

Add an ephemeral Side Chat workflow that branches from an assistant reply,
opens as an interactive Side Panel target, and leaves the parent Chat draft,
scroll, transcript, and active generation untouched. A Side Chat is hidden from
normal Chat and Messenger lists until the operator explicitly keeps it.

The frozen completion decision is: `Done & return` immediately makes the Side
Chat read-only. Closing its Side Panel tab removes the only ordinary UI entry;
the hidden record remains available to audit and governance links but is not
listed as history.

## Product Logic Alignment

Affected contracts are `CHAT.LIFECYCLE.001`, `CHAT.FORK.001`,
`CHAT.SIDE.PANEL.001`, `MESSENGER.ATTENTION.001`, and the dedicated
`CHAT.SIDE.CHAT.001` lifecycle contract added after explicit user approval on
2026-07-20. The registry now records the implemented Side Chat entry points,
hidden lifecycle, promotion, ownership, evidence, and terminal states.

## Scope

In scope:

- `/side` composer command and an assistant-message `Open side chat` action.
- `Side Chat` in the Side Panel empty/add-target surface.
- A provisional client draft; the server record is created on first Send.
- Exact source conversation and assistant-message anchoring.
- An interactive Side Panel transcript and composer using the normal Chat
  runtime path.
- A two-hour send window refreshed by persisted Side Chat messages.
- `Done & return`, which closes mutation immediately and leaves a read-only tab
  until the operator closes it.
- Closing a completed/expired ephemeral tab removes its ordinary UI entry.
- `Keep in Messenger`, preserving the same conversation id and placing it in an
  existing source group when one exists; otherwise it becomes an ungrouped
  Messenger Chat.
- Organization and operator ownership checks, idempotent creation, activity
  logging, and visibility filtering.
- Automated server/UI/E2E coverage and rendered browser verification.

Out of scope:

- A discoverable Side Chat history/archive.
- Reopening a completed Side Chat for mutation.
- Automatically deleting hidden audit data.
- Cross-device restoration of an unsent provisional draft.
- Editing `doc/product/**` without a separate explicit approval.

## Implementation Plan

1. Extend the conversation model with Side Chat kind, state, visibility,
   expiry, completion/keep timestamps, and an owner-scoped idempotency key.
2. Add an isolated Side Chat service for anchored creation, source-context
   copying, owner checks, expiry/touch, completion, and Messenger promotion.
3. Add organization-scoped create plus chat-scoped complete/keep endpoints.
   Guard normal send/stream mutation with Side Chat ownership and lifecycle.
4. Filter hidden Side Chats from Chat lists and ordinary Messenger summaries;
   keep approvals, failed runs, and other control-plane attention in their
   existing synthetic Messenger surfaces.
5. Add a typed `side_chat` Side Panel target and provisional-draft state.
6. Wire `/side`, assistant-message anchoring, and Side Panel empty state to the
   same creation flow.
7. Render the Side Chat transcript, expiry clock, composer, Done action, and
   Keep action in the Side Panel.
8. Add production-shaped E2E coverage for parent-state preservation, expiry,
   immediate read-only completion, close disappearance, and promotion.

## Design Notes

- The UI label is `Side Chat`; the persisted kind is `side_chat`.
- Creation is idempotent by organization, owner, and client mutation id.
- Source context is copied through the anchor, but copied messages do not gain
  new run/output ownership.
- Completion and expiry preserve the record for audit but do not create a
  history list.
- Promotion never creates a group implicitly. It joins the source's existing
  group when one exists; otherwise the promoted Chat is simply listed.
- The in-progress Chat service extraction already present in the working tree
  is unrelated and must not be staged with this feature.

## Success Criteria

- All three entry points open the same provisional Side Chat workflow.
- First Send creates exactly one hidden Side Chat and starts a real agent run.
- Parent Chat composer value, scroll position, transcript, and generation are
  unchanged.
- Hidden Side Chats do not appear in Chat lists, Messenger lists, recent chats,
  search, or custom groups.
- Expired and completed Side Chats reject sends with zero side effects.
- `Done & return` makes the panel read-only immediately; closing its tab leaves
  no normal navigation path back.
- `Keep in Messenger` preserves the conversation id and makes it durable and
  visible with correct group placement.
